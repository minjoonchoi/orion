# 상세 페이지 UI 공통 규칙

## 구조

1. 경로, 이름, 설명과 객체 전체에 대한 작업(동기화·영향도 검토)을 상단에 배치한다.
2. 기본 정보는 `DetailTabs`의 `info` 항목으로 선언한다. 공통 컴포넌트가 이를 탭 밖의 상단 영역에 항상 표시한다. 화면에 sticky로 고정하지 않는다.
3. 관계별 목록은 하단의 단일 탭 영역에 배치한다. 관련 항목 테이블을 별도로 나열하지 않는다.
4. 기본 정보만 있는 결재 상세에는 불필요한 빈 탭을 만들지 않는다.

## 탭과 이동

- 목록 탭은 `이름 (전체 개수)`로 표시하며, 검색 결과 개수와 구분한다. 0개여도 탭을 유지하고 빈 상태를 표시한다.
- `?tab=<stable-id>`로 선택 상태를 기록한다. 새로고침, 뒤로/앞으로 이동과 직접 링크를 지원한다.
- 누락되거나 잘못된 tab 및 이전 `tab=info`는 첫 목록 탭으로 대체한다. 기본 정보는 항상 보인다.
- 목록의 관계 개수는 해당 상세 탭으로 관계한다.
- 검색·필터·정렬·페이지 이동은 탭의 표 내부에 둔다. BrowseTable의 표별 URL 상태는 탭 전환 시 유지한다.
- 키보드 방향키와 Enter/Space로 탭을 선택한다. 비활성 패널은 접근성 트리에서도 숨긴다.

## 작업 버튼

- 역할의 사용자 추가·해제는 역할 상세의 사용자 탭에서 수행한다. 플랫폼 멤버 추가는 플랫폼 상세의 멤버 탭에서 수행한다. 사용자·멤버 상세에서는 역방향 추가 UI를 제공하지 않는다. 정책 부여/해제는 역할의 정책 탭 상단에 배치한다.
- 객체 전체에 영향을 주는 동기화·영향도 검토는 페이지 상단에 둔다.
- 부여·부여 변경의 기존 선택 → 영향도 검토 흐름은 유지한다.

## 페이지별 목록

| 상세            | 목록 탭                                               |
| --------------- | ----------------------------------------------------- |
| 사용자          | 플랫폼, 소속 조직, 플랫폼별 사용자 역할               |
| 조직            | 멤버, 서비스 어카운트(API 키 포함), 관리 서비스, 역할 |
| 서비스 어카운트 | 역할, API 키                                          |
| 역할            | 사용자, 조직, 서비스 어카운트, 정책                   |
| API 키          | 결재 이력, 서비스 어카운트                            |
| 결재 템플릿     | 관계 결재                                             |
| 결재            | 기본 정보만 표시                                      |
| 워크스페이스    | 페이지, 관계, 동기화 이력, YAML                       |
| 페이지          | Action, 관계, 동기화 이력, YAML                       |
| 서비스          | 엔드포인트, 관계, 동기화 이력, YAML                   |
| 엔드포인트      | 요청 필드, 응답 필드, 관계, 동기화 이력, YAML         |
| 업무 도메인     | Action, 관계, 동기화 이력, YAML                       |
| Action          | 정책별 응답 범위, 관계, 동기화 이력, YAML, 권한 평가  |
| 정책            | Action별 응답 정의, 관계, 동기화 이력, YAML           |

YAML·권한 평가처럼 목록이 아닌 탭에는 개수를 표시하지 않는다. 관계는 참조 방향을 보여주는 탐색 뷰이며, 개별 유형의 주 목록과 구분한다. 조직 API 키는 별도 탭을 만들지 않고 서비스 어카운트 목록에는 API 키 개수만 표시하고, 클릭하면 해당 어카운트의 API 키 탭으로 이동한다. 키 목록은 관리 서비스별 필터와 관리 서비스·발급일·만료일을 제공한다. 기존 조직 `tab=api-keys` 링크는 서비스 어카운트 탭을 연다.

## 구현 및 검토

- 공통 레이아웃: `src/features/identity/detail-tabs.tsx`
- 공통 목록: `src/features/identity/browse-table.tsx`
- 관계 탭: `src/features/relationships/related-records.tsx`의 `relatedTabs`
- 새 상세 페이지에서는 별도의 탭 상태·기본 정보 탭·관련 테이블 나열 패턴을 만들지 않는다.
- API 계약과 한국어/영어를 함께 유지한다.
- 기본 정보 유지, URL 직접 접근·뒤로 이동, 빈 목록, 관계 링크, 모바일 가로 넘침과 키보드 접근성을 검증한다.

역할 상세의 탭 이름은 메뉴 이름과 동일하게 표시한다. 역할 수신 대상인 사용자 → 조직 → 서비스 어카운트를 먼저 배치하고, 역할이 제공하는 권한인 정책을 마지막에 배치한다.

플랫폼 상세는 멤버 → 워크스페이스 → 역할 → 인증 설정 순서로 표시한다. 멤버 상세 역할은 사용자 역할을 조회한다. 역할 변경은 역할 상세에서 수행한다.

관계 추가는 대상을 받아주는 주체의 상세 화면에 배치한다. 예: 플랫폼 ← 사용자(멤버), 역할 ← 사용자. 역방향 상세에는 조회·이동만 제공하며 중복된 추가 진입점을 만들지 않는다.
