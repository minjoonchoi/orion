# 서비스 어카운트 조회

사용자·조직 그룹에 서비스 어카운트 메뉴를 추가합니다.

- `/service-accounts`: 이름·ID·설명·조직 검색, 상태·조직 필터, 이름·역할 수·API 키 수·등록일 정렬, 페이지 이동
- `/service-accounts/[id]`: 기본 정보, 역할, API 키 탭
- 기본 정보: ID, 이름, 설명, 상태, 소속 조직, 등록일, 최근 사용일
- 역할: 직접 연결된 역할 목록과 역할 상세 이동
- API 키: 연결된 키의 ID·이름·마스킹 식별 표시·상태·만료일, 상태 필터와 키 상세 이동

상세 탭은 `?tab=roles`, `?tab=api-keys`로 공유합니다. 새로 고침과 뒤로 가기를 지원하며 잘못된 탭은 기본 정보로 표시합니다. 없는 ID, 연결 항목 없음, 검색 결과 없음, 사용 기록 없음, 만료일 없음을 구분합니다. 날짜는 한국 시간 기준입니다.

조직 상세의 서비스 어카운트 이름에서 독립 상세 화면으로 이동합니다. 서비스 어카운트 상세의 소속 조직·역할·API 키는 기존 상세 화면으로 연결됩니다.

## 데이터 범위

계정은 기존 `identity/fixtures.ts`의 조직 서비스 어카운트 데이터를 재사용합니다. 역할·키 관계는 `service-accounts/fixtures.ts`에 명시한 예제 매핑입니다. 역할과 키는 기존 조회 데이터에서 선택하며, 조직에 속한다는 이유로 역할이나 키를 자동 상속하지 않습니다. API 키의 기존 소유자 필드는 그대로 유지하며 계정과의 연결 관계를 별도로 표시합니다.

서버 페이지는 `serviceAccountRepository`를 호출합니다. 실제 API 계약 확정 후 조회 어댑터와 관계 스키마를 교체합니다. 계정 생성·수정·삭제, 역할/키 연결 변경, 키 발급, 실제 인증·인가 및 유효 권한 계산은 범위에 포함하지 않습니다. 비밀 키 원문은 포함하지 않습니다.

## 검증

`npm run check`, `npm run build`, `npm run test:e2e -- --workers=2`.
메뉴·목록 필터·정렬, 조직↔계정과 역할·키 이동, 탭 복원, 빈 관계·없는 ID·선택적 날짜, 접근성과 모바일 가로 넘침을 확인합니다.
