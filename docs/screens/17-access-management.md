# 멤버·권한 관리

상태: 제품 UI 구현됨 / 운영 API 통합 미완료. 소스: `src/features/access-ui/`, 사용자·플랫폼 화면 및 신규 페이지. 기존 플랫폼을 관리 범위로 사용하며 별도의 테넌트 모델을 추가하지 않는다.

## 멤버·역할 편집

- 멤버 상태와 사용자 재직 상태는 별개다. 중지·제외는 사용자 및 다른 플랫폼 멤버십을 삭제하지 않는다. 역할 부여를 자동 회수하지 않는 동작을 검토 단계에 명시한다.
- 검색/필터 변경 시 선택을 유지하고 전체 선택 수와 해제 수단을 제공한다. 상태가 이미 같은 대상만 선택한 경우 해당 상태 변경 버튼을 비활성화한다.
- 역할 생성은 플랫폼·이름·설명을 입력하고 검토 후 생성한다. 생성 후 상세로 이동한다. 기존 역할의 플랫폼을 바꾸지 않는다.
- 사용자와 조직 부여는 받는 역할의 상세에서만 변경한다. 다른 역할은 보존한다. 정책 만료는 해당 역할의 binding에만 적용한다.
- 정책 선택에서 추가·해제·유지와 최종 만료값을 검토한다. 과거 만료일은 새 입력으로 허용하지 않는다. 서비스 어카운트 탭은 기존 조회를 보존한다.

## 종합 조회·접근 확인

- 일반 조회는 중복 제거한 역할 목록과 부여 방식, 가능한 업무를 표시한다. 경로 상세는 접근 확인에서 펼쳐 확인하며 업무 가능 여부는 시안의 활성 멤버십 조건과 정책 연결을 함께 확인한다.
- 멤버십 부재/중지, 정책 없음, 관계 만료를 거부 사유로 구분한다. 입력 변경 시 이전 결과를 지우고 재확인을 요구한다. 조회 이후 권한 상태가 바뀌면 이전 결과를 최신 결과처럼 표시하지 않는다.
- 운영 응답 DTO는 허용/거부, 이유, 근거 경로, 반환 필드·마스킹을 제공해야 한다. 시안의 Action 카탈로그와 단순 경로 평가는 UI 상태 확인용이며 실제 인가 엔진이 아니다. deny 합성·정책 충돌·실시간 외부 데이터 평가는 제품 통합 과제다.

## 신청·내 접근 권한

- 내 접근 권한의 조회 플랫폼 행에는 필터만 표시한다. 접근 확인·권한 신청 바로가기를 중복 배치하지 않는다. 권한 신청은 페이지 상단에서 시작하며 사용자 상세의 접근 확인 링크는 유지한다.
- 현재 사용자는 기존 세션 응답의 actorId를 사용한다. 다른 사용자를 가장하는 선택 UI를 제공하지 않는다.
- 직접 또는 조직을 통해 보유한 역할과 동일한 진행 중 신청은 재신청을 차단한다. 플랫폼 변경 시 역할 선택을 초기화한다.
- 사유는 공백 불가·최대 2,000자. 종료일은 선택이며 비우면 무기한이다. 종료일·정책 binding 만료는 별개의 정보다.
- 검토 화면은 신청자·플랫폼·역할·기간·사유를 표시한다. 제출 후 내 신청 탭으로 이동하며 역할은 추가하지 않는다.
- 신청 상세에서 본인의 대기 신청만 취소하고 확인 단계를 거친다. 취소는 보유 권한을 바꾸지 않는다.
- 플랫폼 담당자 검토는 시안의 제안 결재선이다. 실제 대상 결정, 템플릿·결재선 스냅샷, 승인/반려와 부여 실행은 기존 결재 모델에 통합할 후속 범위이며 이 시안에서 완료로 표시하지 않는다.

## 재사용과 상태 범위

`BrowseTable`, `DataTable`, `DetailTabs`, `Dialog`, `Field`, `Input`, `Select`, `Button`, `Badge`, `Details`, `Summary`를 재사용한다. 대상 선택→검토의 공통 흐름은 `EditDialog`로 공유한다. 신규 화면은 한/영과 좁은 화면을 확인한다.

`src/features/access-ui/store.ts`는 페이지 간 조작 결과를 공유하는 메모리 어댑터다. 새로고침하면 초기화된다. 운영 API의 현재 사용자 권한·원자 변경·충돌·영속 저장을 대체하지 않으며 운영 사용 전 repository/세션 경계를 통합해야 한다. 현재 변경은 브라우저 메모리에만 유지되며 새로고침하면 초기화된다.

## 검수 기준

멤버 중지 후 동일 사용자의 접근 거부, 다른 플랫폼 유지, 조직 부여와 직접 부여 방식 구분, 정책 해제/만료 반영, 요청 중복 차단, 제출 후 역할 불변, 취소 후 보유 권한 불변, 역할 생성 후 상세 이동, 새로고침 초기화, 한/영 주요 화면, 모바일 넘침·키보드 모달을 확인한다.

배치·간격은 [공통 화면 규칙](00-common.md#공통-배치간격-규칙)의 토큰을 사용한다. `ui-layout-stack`이 섹션 사이 간격을, `ui-panel`이 카드 안쪽 여백을 소유한다. 제목·요약·탭의 margin 중복을 제거하며 개별 화면에서 임의의 간격을 추가하지 않는다.

## 일반 조회 단순화와 변경 검토

구현된 UI: 사용자 권한 종합과 내 접근 권한은 권한 목록·가능한 업무로 구성한다. 역할과 업무는 중복 제거하며 부여 방식만 표시한다. 경로·정책별 만료·접근 가능한 Action 요약 개수는 일반 조회에서 제외한다. 가능한 업무는 시안 평가에서 허용된 항목이며 운영 정책 평가 완료를 뜻하지 않는다.

접근 확인은 결과와 사유를 먼저 표시하며 상세 근거·데이터 범위는 펼쳐서 확인한다. 변경 영향도는 기존 다단계 경로를 유지하고, 조직 구성원을 포함한 대상별 정의의 변경 전후 비교를 먼저 표시한다. 모든 역할의 직접 참조 정책을 비교하되 최종 실효 권한으로 표시하지 않는다. 정의 기반 검토는 응답 필드·마스킹 변화까지 비교한다. graph 전용 검토의 필드 정보 미제공과 양쪽 모델의 멤버십·조건부 정책 등 미평가 범위는 확인 필요로 명시한다.

API 데이터 모드의 기존 역할 사용자 추가/해제는 서버 저장 경로를 유지한다. 새 역할 관리 UI는 데모 모드의 메모리 어댑터이며 운영 API 전환은 미완료다. 서버 렌더링의 초기 상태는 요청별로 분리한다.
