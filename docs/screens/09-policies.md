# 정책

정책은 업무를 파악하기 쉬운 권한 단위다. 역할 수신자는 여러 사용자·조직·서비스 어카운트일 수 있지만, 하나의 정책이 여러 페이지를 포괄하는 범용 묶음이 되지 않게 한다. 현재 YAML 정책과 P18의 결재 관리 정책은 관리 출처가 다르다.

## POL-01 목록 — `/policies`

구현 M: YAML 정책 이름·ID 검색, 동기화 상태 필터, 이름·유형·상태·변경 검토/Sync. P18: API 키 결재 관리 정책 표를 별도로 제공하고 담당 계정·서비스·endpoint 수를 표시한다. 기획 원칙은 출처를 명확히 구분하여 일반 YAML Sync로 결재 정책을 덮어쓰지 않는 것이다.

## POL-02 YAML 정책 상세 — `/policies/{policyId}` (M)

| 영역           | 표시/기능                                                                    |
| -------------- | ---------------------------------------------------------------------------- |
| 기본 정보/상단 | ID, 이름, 설명, 유형, Synced/Out of sync, 영향도 검토, 동기화                |
| Action 탭      | allow/deny 효과, 선택적 단일 page 참조, 명시적 Action 목록, 각각의 응답 규칙 |
| 관계 탭        | page/domain Action/endpoint와 권한 경로 탐색                                 |
| 동기화 이력    | 해당 정책의 revision·수행자·시각, 이전 revision 복원                         |
| YAML           | 정책 정의, 부모 범위가 포함된 ref                                            |

정책을 역할에 부여하는 작업은 역할 상세의 책임이다. 정책 자체에 사용자 부여 모달을 추가하지 않는다. 정책 내용 수정/삭제는 YAML→변경 관리→검토→Sync 경로다.

## POL-03 응답 제어 — 정책 상세의 Action별 표시 (M)

- 정책 resources는 optional 단일 page와 명시적 Action N개다. workspace는 page ref 안에서 특정되므로 별도 중복 권한으로 나열하지 않는다.
- page가 있으면 명시한 Action이 그 페이지가 사용하는 Action인지 검증한다. page가 없으면 S2S 정책이 될 수 있다.
- allow: endpoint response.fields의 field ref를 선택하고 필요한 masking을 정의한다. `fields: []`는 반환 필드 없음이다.
- `body: none`은 응답 body 없음이다. fields/unmask와 혼합하지 않는다.
- unmask는 특정 field의 마스킹 해제 권한이며 필드 반환/호출 권한을 새로 만들지 않는다.
- deny는 Action 호출 자체의 거부이며 response 설정을 허용하지 않는다.
- email / keep-last / redact 등 모델이 지원하는 마스킹만 사용한다. 동일 Action의 정책 합성은 [데이터 정의](14-data-and-permissions.md)를 따른다.

단일 정책의 응답 정의와 여러 정책을 합성한 실제 평가 결과를 구분한다. 최종 결과는 Action의 권한 평가에서 확인한다.

## POL-04 결재 관리 정책 상세 — 동일 상세 경로 (P18)

관리 방식(결재), API 키 관리 ID, 전용 Orion 역할, 서비스 어카운트와 승인된 endpoint 목록을 표시한다. 탭: 엔드포인트, 열람 가능한 결재. 필드 선택·마스킹을 임의 추가하지 않는다. 수정은 같은 키의 교체 결재, 제거는 폐기 결재로 수행한다.

정책+역할은 최초 발급 성공 시 세트로 생성한다. 교체는 기존 ID를 유지하고 endpoint를 추가/삭제한다. 이 직접 endpoint 정책과 domain Action 정책은 현재 다른 모델이며, 어느 우선순위로 운영 인가에 합성되는지 확정·구현되기 전에는 동일 엔진으로 완료되었다고 표현하지 않는다.

## 수용 기준

페이지를 누락한 정책도 유효한 S2S 구성이 될 수 있다. 페이지/Action을 명시했을 때 2차 일관성 검증을 수행한다. 역할-정책 만료가 정책 정의에 저장되지 않는다. 사용 중인 정책 삭제는 참조/부여 무결성을 검사하고, 영향도에는 선택한 정책을 통해 영향을 받는 직접 대상만 포함한다.
