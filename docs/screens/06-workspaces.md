# 워크스페이스와 페이지

구현: M. 소스: `src/features/definitions/screen.tsx`, `config/definitions/*.yaml`. 워크스페이스는 플랫폼의 UI 공간, 페이지는 그 하위 화면 정의다. YAML은 workspace 문서에 pages를 포함하지만 조회·Sync·이력은 정규화된 개별 항목 기준이다.

## WSP-01 목록 — `/workspaces`

표: 이름, 전체 식별자, 유형, Synced / Out of sync, 변경 검토·동기화 작업. 플랫폼 필터와 이름/ID/경로 검색, 동기화 상태 필터를 제공한다. 이름→상세, Out of sync의 변경 검토→YAML diff/영향도, 동기화→공통 2단계 검토. 목록은 적용된 상태와 변경 후보를 구분할 수 있어야 한다. 플랫폼 소속은 directory의 워크스페이스 매핑을 사용한다.

## WSP-02 상세 — `/workspaces/{workspaceId}`

| 영역        | 기능                                                                 |
| ----------- | -------------------------------------------------------------------- |
| 상단        | 이름, ID, 설명, 소속 플랫폼 링크, 동기화 상태, 영향도 검토, 동기화   |
| 페이지 탭   | 페이지 이름·식별자·상태, 페이지 상세 이동                            |
| 관계 탭     | 참조·역참조 객체를 방향과 함께 탐색                                  |
| 동기화 이력 | 해당 워크스페이스 revision·적용자·시각·execution, 이전 revision 복원 |
| YAML        | 해당 항목의 정규화된 YAML 확인                                       |

워크스페이스를 선택했다고 모든 페이지를 자동으로 Sync하거나 모든 Action 접근 권한을 부여하지 않는다. 미지정 플랫폼 링크를 임의 값으로 만들지 않아야 하며 현 구현의 소속 누락 처리는 보완 대상이다.

## PAG-01 하위 목록 — `/pages[?parent={workspaceId}]`

LSB 독립 메뉴는 없다. 워크스페이스 하위 탐색 및 직접 URL용이다. 부모 필터가 있으면 해당 워크스페이스의 페이지, 없으면 접근 가능한 페이지를 나열한다. 이름·부모 포함 ID·유형·동기화 상태와 변경 작업을 제공한다. 같은 page ID가 다른 워크스페이스에 있어도 행/링크를 구분한다.

## PAG-02 상세 — `/pages/{workspaceId}~{pageId}`

기본 정보: 이름, 복합 ID, 유형, 설명. 경로와 workspace 참조는 YAML/관계에서 확인 가능하며 운영 화면에서 누락되지 않도록 한다. 탭은 **Action → 관계 → 동기화 이력 → YAML**이다.

- Action 표는 이 페이지가 사용하는 domain/action 참조다. Action 상세로 이동하여 엔드포인트와 정책별 응답을 탐색한다.
- 페이지의 Action 목록은 필요 기능을 선언하는 관계다. 페이지 권한만으로 Action을 허용하지 않는다.
- 같은 엔드포인트를 다른 형태로 사용하는 페이지는 다른 Action을 참조할 수 있다. 실제 응답은 해당 Action에 적용된 정책 합성 결과를 따른다.
- 수정/삭제는 YAML 변경을 통해 Out of sync로 만들고 검토 후 Sync한다. 화면에서 직접 경로를 고쳐 즉시 적용하지 않는다.

## 상태·검수

삭제는 YAML에서 단순히 항목을 빼는 것이 아니라 `state: absent`로 명시한다. 참조 중인 페이지/Action 관계를 깨뜨리는 삭제는 차단하거나 참조 해소 변경을 함께 검토한다. 페이지의 과거 revision 복원은 현재의 다른 부여와 형제 페이지를 유지한다. 단일 상세와 변경 관리 복수 선택의 검토 규칙은 같아야 한다.

수용 기준: parent 포함 참조의 정확성, 플랫폼별 목록 범위, 페이지→Action→정책 이동, 페이지/Action 권한의 독립성, 해당 항목 이력만 표시됨을 확인한다. 플랫폼 소속을 YAML에 어떤 필드로 소유할지는 현재 directory 매핑과 별도의 서버 통합 과제다.
