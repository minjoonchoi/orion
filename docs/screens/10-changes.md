# 변경 관리: YAML diff·영향도·Sync·롤백

구현: M. `/resources`가 리소스 관리와 Sync를 통합한다. Argo는 동작 예시였으며 제품 의존성/메뉴가 아니다. Git merge 이후 Cloud Config의 변경 정의를 가져오는 서버 파이프라인을 전제로 하되 **명시적 Sync 이전에는 적용하지 않는다**.

## CHG-01 통합 목록 — `/resources`

| 구역      | 기능                                                                          |
| --------- | ----------------------------------------------------------------------------- |
| 요약      | Out of sync, Synced 수. ‘현재 DB’, ‘cloud config 후보’ 같은 상태명 사용 안 함 |
| 검색·필터 | 이름/ID/경로, 리소스 유형, 동기화 상태. 부모/선택 상태를 URL로 복원           |
| 유형      | workspace, page, service, endpoint, domain, Action, policy                    |
| 표        | 선택 체크, 이름/ID, 유형, 간결한 상태, 변경 검토·동기화                       |
| 선택 작업 | 선택 건수, 선택 항목 동기화, 선택 범위 영향도 검토, 선택 해제                 |
| 이동      | 이름→유형별 상세. 필터와 선택의 문맥 유지                                     |

변경 없는 항목에 불필요한 세부 상태 배지를 추가하지 않는다. Sync는 파일 전체가 아니라 정규화된 개별 key 또는 사용자가 고른 key 집합 단위다. Git에서 항목이 빠졌다는 이유만으로 자동 삭제하지 않는다.

## CHG-02 변경 검토 — 행/상세에서 모달

같은 변경 집합을 **YAML diff / 영향도** 두 뷰로 제공한다. diff는 기준 revision과 변경 revision의 정규화 YAML 차이를 보여준다. 추가·수정·삭제 항목을 식별하고 의미 없는 표기 순서 변화는 억제한다. 한 뷰에서 다른 뷰로 전환해도 대상이 바뀌지 않는다. 조회 검토만으로 적용되지 않는다.

## CHG-03 Sync — 상세 단일·목록 복수 공통 모달

| 단계                       | 선택/검토                                                                                                   |
| -------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 1. 대상 확인               | 사용자가 고른 항목과 필수 참조 포함 항목을 구분. 정책→page/Action→endpoint→부모 정의를 필요한 범위에서 포함 |
| 2. 변경사항 및 영향도 검토 | 실제 변경 key, YAML diff, 직접 영향 대상, 정책/역할 경로, 차단 사유. 완료 버튼은 ‘동기화 적용’              |
| 적용                       | preview token과 revision/sourceRevision/만료를 재검증. 정의와 필요한 의존 변경을 원자적으로 적용            |
| 완료                       | 변경된 항목의 상태·revision·개별 이력 갱신. 목록의 불필요한 선택 제거                                       |

참조 자식의 형제까지 자동 포함하지 않는다. 정책에 없는 Action 권한을 생성하지 않는다. 미존재 참조, 사용 중인 field 삭제, 부여 중인 정책 삭제, page와 Action 불일치 등은 차단한다. 관련 변경을 함께 선택하여 참조를 해소할 수 있다. 검토 이후 소스/권한/revision 변경은 재검토를 요구한다.

## CHG-04 영향도 탐색 — 목록형 통합 뷰

최상위는 **직접 사용자·조직·서비스 어카운트** 통합 목록이고 유형 배지·필터를 제공한다. 유형별 탭이나 Finder식 다열 계층보기를 사용하지 않는다. 대상을 펼치면 들여쓰기/경로 구분으로 **역할 → 정책(효과·만료) → Action/선택 리소스** depth를 보여준다.

- 단일/선택 리소스의 before/after 양쪽 관계를 기준으로 탐색한다. 무관한 전체 플랫폼 영향을 보여주지 않는다.
- 정책 Sync는 해당 정책이 부여된 역할을 통해 직접 대상을 찾고 필수 참조 리소스 변경을 함께 검토한다.
- 조직 경유 사용자는 목록과 집계에 포함하지 않는다. 조직 자체를 대상으로 유지한다.
- 경로 해제가 다른 경로의 권한까지 없앴다는 의미는 아니다. 관계 영향과 최종 허용/거부를 구분한다.
- 대상/역할/정책/리소스 검색, 대상 펼침, 관련 상세 이동을 지원한다. 중복은 유형+ID로 제거한다.
- 전체 영향 데이터를 받지 못했으면 ‘확인할 수 없음’을 표시한다. 누락된 서비스 어카운트를 0명으로 표시하지 않는다.
- 페이지 단위 추가 조회로 긴 경로의 스크롤을 제한한다. 서버 페이지 계약이 없는 현재 뷰는 받은 전체 graph 안의 클라이언트 분할이다.

## CHG-05 항목별 이력과 롤백 — 각 상세의 동기화 이력 탭

revision, 적용 시각, 수행자, source/execution과 정의를 제공한다. 이전 revision 선택→복원 diff/영향도 검토→롤백 적용. 롤백은 과거 상태를 새로운 revision으로 기록하며 이력을 삭제하지 않는다. 해당 key 외 다른 정의·역할 부여를 되돌리지 않는다. 현재 참조를 깨뜨리는 복원은 차단한다. 삭제된 항목의 이력도 서버는 보존해야 한다.

독립 이력 메뉴는 없다. `/resource-sync`, `/resource-sync/history`는 `/resources`, `/policy-sync`, `/policies/sync`는 `/resources?type=policies`로 이동한다.

## 수용 기준·미완료

상세 단일 Sync와 목록 한 건 선택의 변경 집합/차단/검토 UX가 동일하다. 복수 선택 시 무관한 변경은 포함되지 않는다. API 계약은 `/definitions/status`, `/definitions/previews`, `/definitions/applications`다. 실제 Git/Cloud Config 수집·영구 revision 저장·분산 배포·서버 원자 적용 및 새 플랫폼 사용자 역할 모델과 영향도 graph 통합은 완료 범위와 구분한다.
