# 플랫폼

## 목적과 경계

플랫폼별 인증 설정, 멤버십, 워크스페이스, 역할을 탐색한다. 사용자는 전역 원장이고 멤버십은 `플랫폼 + 사용자` 관계다. 역할은 사용자에게 부여되며 멤버에 저장하지 않는다. 서비스 어카운트를 플랫폼 멤버로 등록하지 않는다. 구현: M. 소스: `src/features/platforms/screens.tsx`, `model.ts`, `repository.ts`.

## PLT-01 목록 — `/platforms`

| 구역 | 표시·행동                                                    |
| ---- | ------------------------------------------------------------ |
| 검색 | 플랫폼 이름·설명 검색, 결과 초기화와 페이지 이동             |
| 표   | 플랫폼, 설명, 로그인 인증, 멤버 수, 워크스페이스 수, 역할 수 |
| 이동 | 플랫폼명→상세, 각 관계 개수→상세 해당 탭                     |
| 작업 | 현재 생성·삭제·OIDC 설정 편집은 제공하지 않는다              |
| 상태 | 공통 로딩/빈 결과/조회 오류 적용                             |

수용 기준: 동일한 사용자가 여러 플랫폼 멤버여도 각 플랫폼의 멤버·역할 건수가 섞이지 않는다.

## PLT-02 상세 — `/platforms/{platformId}`

상단 기본 정보: ID, 플랫폼명, 인증 제공자, 인증 주체(플랫폼 멤버). 탭 순서는 **멤버 → 워크스페이스 → 역할 → 인증 설정**이다.

| 탭           | 표시                                             | 작업/이동                                     |
| ------------ | ------------------------------------------------ | --------------------------------------------- |
| 멤버         | 닉네임, 이메일, 상태, 사용자의 이 플랫폼 역할 수 | 멤버 상세, 멤버 추가(PLT-04)                  |
| 워크스페이스 | 이 플랫폼의 워크스페이스 목록                    | 워크스페이스 상세                             |
| 역할         | 플랫폼 역할, 설명, 대상·정책 건수                | 역할 상세, 부여는 역할 상세에서 수행          |
| 인증 설정    | provider, issuer, client ID, 로그인 API 경로     | 조회 전용. client secret·토큰은 표시하지 않음 |

설정 경로는 로그인 API를 설명하는 정보다. 화면에 보인다는 사실이 Okta 등록/콜백 검증이나 운영 로그인 가드의 구현을 보장하지 않는다.

## PLT-03 멤버 상세 — `/platforms/{platformId}/members/{memberId}`

기본 정보: 플랫폼, 사용자 카탈로그 링크, 닉네임/이메일, 멤버 상태, 인증 방식. 관계 탭은 역할이며 **사용자가 보유한 현재 플랫폼 역할**을 조회한다. 사용자 상세·역할 상세로 이동할 수 있지만 이 화면에서 역할을 직접 추가/해제하지 않는다.

- 멤버 ID는 플랫폼 범위와 함께 해석한다. 다른 플랫폼의 같은 로컬 ID를 대체 조회하지 않는다.
- 멤버 상태(활성/중지)와 사용자 재직 상태(재직/휴직)는 서로 다른 데이터다.
- 역할 보유만으로 활성 멤버십을 생성하거나 로그인 가능 상태로 바꾸지 않는다.
- 멤버 상태 변경/삭제 UI는 현재 범위에 없다.

## PLT-04 멤버 추가 — 플랫폼 상세의 모달

| 단계           | 내용                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------- |
| 1. 사용자 선택 | 사용자 카탈로그 검색·다중 선택. 해당 플랫폼의 기존 멤버는 중지 상태를 포함하여 제외          |
| 2. 검토        | 받는 플랫폼, 선택한 사용자, 멤버십만 생성됨을 표시                                           |
| 적용           | 같은 플랫폼에 선택 사용자들을 원자적으로 추가. 중복/미존재 사용자/revision 충돌 시 전체 실패 |
| 완료           | 멤버 목록과 개수 갱신. 사용자 상세의 플랫폼 탭에서도 확인                                    |

수용 기준: 신규 멤버 추가가 기존 사용자 역할·다른 플랫폼 멤버십을 변경하지 않고, 중지 멤버를 자동 활성화하지 않는다. 멤버십 이전에 부여한 역할은 그대로 유지한다.

## API·운영 의존

`GET /platform-directory`, `POST /platforms/{id}/members`. 서버는 현재 운영자의 플랫폼 관리 권한과 revision을 검증한다. 카탈로그·워크스페이스 소속·역할의 조회 원천이 일치해야 한다. 현재 OIDC 설정 편집, 멤버십 상태 관리, 조직 역할 상속의 실제 로그인 게이트는 [미완료 표](15-gaps-and-decisions.md)에 따른다.
