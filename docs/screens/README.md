# Orion 메뉴별 화면 기획서

> **UI 구현 상태**: 승인된 화면을 제품 소스에 반영했다. 멤버·권한 UI의 메모리 상태와 서버 연동 제약은 [멤버·권한 관리](17-access-management.md)를 따른다.

대상: 사내 백오피스의 통합 인증·인가를 운영하는 관리자, 플랫폼 담당자, 서비스 담당자, 결재 참여자. 이 문서는 지금까지의 제품 합의와 실제 화면을 함께 정리한 **화면 기획 기준 문서**다. UI가 있다는 이유만으로 운영 인증·인가나 영구 저장이 완료되었다고 판단하지 않는다.

## 기준과 읽는 순서

- **구현됨**: 명시된 화면·모델·어댑터가 존재함. 운영 서버 연동 완료를 의미하지 않는다.
- **부분 구현**: 화면 일부 또는 다른 모델과의 통합이 남아 있음. **미구현/목표**: 합의된 요구지만 현재 화면·서버에 반영되지 않음.
- 메뉴 표는 UI 범위 요약이며 상세 제약과 서버 연동 과제는 각 화면과 [미완료 목록](15-gaps-and-decisions.md)을 함께 확인한다.
- 먼저 [공통 규칙](00-common.md), 각 메뉴 문서, [데이터·권한 정의](14-data-and-permissions.md), [미완료·결정사항](15-gaps-and-decisions.md), [검수표](16-acceptance.md)를 읽는다.
- 상세의 기본 정보는 항상 위에 표시하며, 아래 탭의 개별 기능을 화면 단위로 정의한다. 모달/검토 단계는 독립 화면 ID를 가진다.

## 메뉴와 화면 목차

현재 LSB는 **5개 그룹, 14개 메뉴**다. 아래 표는 제품 소스에 반영된 메뉴 배치다. 결재 템플릿은 결재 메뉴 안의 탭으로 유지한다. 페이지·엔드포인트·Action은 하위 탐색 화면이며 별도 LSB 메뉴로 늘리지 않는다.

## 최종 합의의 핵심

1. 사용자는 전역 카탈로그이고 플랫폼 역할의 수신자다. 플랫폼 멤버십은 가입·활성 상태를 보유하며 역할을 복사해 보유하지 않는다.
2. 서비스 어카운트는 플랫폼에 종속되지 않는 서버 통신 주체다. API 키로 인증하고 Orion 역할을 사용한다.
3. 관계를 추가하는 작업은 받는 쪽 상세에서 한다. 플랫폼 상세에서 멤버 추가, 역할 상세에서 사용자 추가. 사용자·멤버 상세는 조회와 이동 중심이다.
4. YAML은 workspace/pages, service/endpoints, domain/actions, policy로 관리한다. 정의 외 위치는 부모 범위가 포함된 ref를 사용한다. 환경/리전, Kubernetes식 wrapper를 넣지 않는다.
5. 정책은 페이지 선택 참조와 명시적 Action 참조를 가진다. 페이지가 Action을 참조한다는 이유로 권한을 자동 부여하지 않는다. S2S 정책은 페이지가 없어도 된다.
6. Sync는 개별 리소스/정책 또는 선택한 집합 단위다. 상태는 Synced / Out of sync. diff와 영향도를 검토한 뒤 명시적으로 적용한다. Argo 연동을 의미하지 않는다.
7. 영향도는 사용자·조직·서비스 어카운트를 통합 목록으로 보여주고 역할→정책 경로를 펼친다. 조직 경유 사용자는 나열하지 않는다.
8. API 키 요청은 결재 템플릿의 인스턴스/스냅샷이다. 승인과 실제 발급은 별도다. 승인 뒤 관리서비스 팀이 입력한 키 원문을 Secret에 저장하고 hash만 관리한다.
9. 결재 열람은 열람자 목록 하나로 판정한다. 요청자와 결재선 사용자·조직을 자동 등록하고 결재선 참가자가 열람자를 추가한다.

## 문서 적용 원칙

각 화면 문서는 현재 요구와 구현 차이를 함께 정의한다. API 필드·불변 조건은 [도메인 계약](../README.md), 작업 절차는 [AGENTS.md](../../AGENTS.md)를 따른다. 요구를 변경하면 화면 ID, 수용 기준, 데이터 계약과 미완료 목록을 함께 갱신한다.

## 화면 확인

[단일 HTML](../demo/orion.html)과 화면별 저장 이미지의 사용법은 [데모 안내](../demo/README.md)를 참고한다. HTML은 제품 컴포넌트와 업무 모델을 재사용하며 실제 Okta·운영 API·AWS 연동은 수행하지 않는다.
