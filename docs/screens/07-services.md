# 서비스와 엔드포인트

구현: M. 서비스는 관리 대상 API 서비스이며 엔드포인트의 부모다. service 문서에 endpoints를 포함한다. 서비스·엔드포인트 ID는 path와 별개다. 같은 path나 같은 로컬 ID가 다른 서비스에 존재할 수 있다.

## SVC-01 목록 — `/services`

이름/ID/경로 검색, 동기화 상태 필터, 이름·복합 식별 정보·유형·상태·변경 작업을 제공한다. 서비스명은 상세로 이동한다. 조직의 관리 서비스 표에서도 같은 상세로 진입한다. 임의 서비스 생성 폼 대신 YAML 정의→변경 관리 흐름을 사용한다.

## SVC-02 상세 — `/services/{serviceId}`

기본 정보: 이름, ID, 유형, 설명. 상단: 동기화 상태, 영향도 검토, 동기화. 탭: **엔드포인트 → 관계 → 동기화 이력 → YAML**.

엔드포인트 목록에서 이름과 서비스 범위의 식별자를 보고 상세로 이동한다. 서비스 자체의 Sync와 하위 엔드포인트 Sync는 별개이며 모든 형제를 자동 선택하지 않는다. 서비스 담당 조직은 결재 카탈로그와 일치해야 하나 YAML 서비스 정의의 필수 정보로 현재 확정되어 있지 않다.

## END-01 하위 목록 — `/service-endpoints[?parent={serviceId}]`

서비스 하위 진입/직접 URL을 제공하고 LSB는 서비스를 활성 표시한다. 표·검색·상태·작업은 리소스 공통 규칙을 따른다. 이름/ID/경로를 검색한다. HTTP method/path만으로 동일 객체 여부를 판단하지 않는다.

## END-02 상세 — `/service-endpoints/{serviceId}~{endpointId}`

| 영역        | 데이터·행동                                                                       |
| ----------- | --------------------------------------------------------------------------------- |
| 기본 정보   | 이름, 복합 ID, 설명, HTTP method/path                                             |
| 요청 필드   | 로컬 field ID, location, JSON/path 위치, 타입, required 등 endpoint가 소유한 명세 |
| 응답 필드   | field ID, response body path, 타입. 정책에서 참조하는 원본 필드 정의              |
| 관계        | 이 endpoint를 사용하는 domain Action 및 정책 경로 탐색                            |
| 동기화 이력 | endpoint 개별 revision과 복원                                                     |
| YAML        | request/response 원본 정의 확인                                                   |

요청과 응답 필드 표를 같은 목록으로 섞지 않는다. Action에 request 필드를 선택적으로 허용하는 UI는 제공하지 않는다. 필드 정의는 endpoint가 소유하고 정책은 참조만 한다. 원문 응답 예시를 통해 민감한 실데이터를 노출하지 않는다.

## 변경·영향도

필드 삭제/타입 변경은 참조 정책의 response 설정에 영향을 줄 수 있다. 선택 endpoint→Action→정책→역할→직접 사용자/조직/서비스 어카운트 경로를 확인한다. 요청 pre-process 또는 임의 스크립트를 모든 리소스에 공통 옵션으로 추가하지 않는다. request param/body 변환은 과거 아이디어이며 현재 실행 계약은 미확정이다. 현재 명시된 실행 범위는 응답 필드 선택·마스킹·해제다.

## API 키와의 관계

발급 요청에서는 관리서비스에 속한 endpoint를 N개 선택한다. 다른 서비스 endpoint를 혼합하지 않는다. 생성 정책은 결재 관리 출처로 표시한다. 이 직접 endpoint 허용 모델과 YAML Action 정책의 운영 인가 통합은 아직 서버 과제다.

수용 기준: 서비스가 다른 동명 endpoint/field가 뒤섞이지 않고, 필드 참조 삭제를 무결성 검증에서 차단하며, endpoint 상세와 Action/정책 사이 왕복 탐색이 가능하다.
