# 역할

목적: 플랫폼별 권한 묶음을 사용자·조직에 부여하고, Orion 역할을 서비스 어카운트에 부여한다. 구현: 플랫폼 사용자 부여 M, 조직/정책 편집 통합 목표, 키 전용 역할 P18.

## ROL-01 목록 — `/roles`

검색은 역할명·설명, 플랫폼 필터를 제공한다. 표는 역할, 플랫폼, 설명, 사용자 수, 서비스 어카운트 수, 정책 수로 구성한다. 이름과 개수는 역할 상세 및 해당 탭으로 이동한다. P18의 결재 관리 역할은 관리 출처가 구분된 별도 표로 노출된다. 동일 이름이라도 플랫폼/ID로 구분한다.

## ROL-02 상세 — `/roles/{roleId}`

기본 정보: ID, 이름, 플랫폼, 역할 수신 범위, 설명. 탭 순서: **사용자 → 조직 → 서비스 어카운트(Orion만) → 정책**. 앞의 세 탭은 권한을 받는 쪽, 정책은 역할이 제공하는 권한이다.

| 탭              | 화면 기능                                              | 현재 상태                                     |
| --------------- | ------------------------------------------------------ | --------------------------------------------- |
| 사용자          | 닉네임/이메일 조회, 사용자 상세 이동, 사용자 추가·해제 | M                                             |
| 조직            | 부여된 조직 조회, 조직 상세 이동                       | M; 플랫폼 범위 편집은 통합 목표               |
| 서비스 어카운트 | 계정 조회, 상세의 역할 탭 이동                         | M; 일반 역할의 직접 편집은 미구현             |
| 정책            | 정책 목록·상세 이동; 목표는 부여·해제와 만료 표시      | M은 조회, 최신 플랫폼 역할에 편집기 통합 필요 |

플랫폼 역할은 멤버가 아니라 사용자에게 부여한다. 아직 해당 플랫폼 멤버가 아닌 사용자에게도 역할을 준비할 수 있다. 역할 부여가 멤버십을 생성하거나 로그인 게이트를 우회하지 않는다.

## ROL-03 사용자 추가·해제 — 역할 상세 모달 (M)

1. 사용자 선택: 역할을 받는 플랫폼/역할을 고정 표시. 추가 시 기존 수신자를 제외, 해제 시 현재 수신자에서 선택. 이름·이메일 검색과 복수 선택.
2. 검토: 사용자 목록, 받는 역할, 해당 역할의 정책을 함께 표시. 최종 기획은 정책→Action/리소스까지 탐색하여 허용 범위를 확인할 수 있어야 한다.
3. 적용: 배치 대상·플랫폼 범위·revision 검증 후 변경. 다른 역할/다른 플랫폼/멤버십은 유지. 실패하면 성공 통지를 하지 않는다.

현재 플랫폼 사용자 부여 모달의 정책 요약은 전체 definitions 영향도 엔진과 통합되지 않았다. 이전 권한 편집기의 리소스 탐색 기능이 새 화면에서도 완료되었다고 취급하지 않는다.

## ROL-04 조직 역할 부여·해제 — 목표

진입은 받는 역할의 조직 탭으로 통일한다. 조직 선택 → 역할/정책/리소스와 직접 영향 조직 검토 → 적용. 다른 플랫폼의 조직 부여를 섞지 않는다. 조직 상세에는 역방향 편집 버튼을 두지 않는다. 조직원을 영향 대상 사용자로 자동 펼치지 않는다. 운영 최종 인가에서의 조직원 합성 규칙은 [미완료 표](15-gaps-and-decisions.md)에 따라 확정·통합한다.

## ROL-05 정책 부여·해제와 만료 — 목표/이전 구현 존재

| 단계 | 입력/표시                                                                                      |
| ---- | ---------------------------------------------------------------------------------------------- |
| 선택 | 정책 복수 선택, 각 역할-정책 부여의 만료 시각 또는 무기한                                      |
| 검토 | 유지·추가·해제, 만료 변경, 정책의 페이지/Action·응답 범위, 사용자·조직·서비스 어카운트 영향    |
| 적용 | policy 자체를 수정하지 않고 binding의 만료/관계만 저장. 서버가 revision과 대상 유효성을 재검증 |

만료는 정책 전역 속성이 아니다. 동일 정책이 다른 역할에 부여된 만료를 함께 바꾸지 않는다. 만료된 경로는 기본 영향 집계에서 제외하고 명시적으로 포함해 볼 수 있다. 단순 관계 해제가 다른 유효 경로까지 제거한다는 의미는 아니다.

## ROL-06 결재 관리 전용 역할 — 같은 상세 경로, P18

기본 정보: 관리 방식(결재), Orion, API 키 관리 ID, 서비스 어카운트, 전용 정책. 탭: 엔드포인트, 열람 가능한 결재. 생성 근거와 접근 범위를 읽기 전용으로 조회한다. 사용자 수신자를 추가하거나 일반 역할 편집으로 수정하지 않는다. 범위 변경은 키 교체, 폐기는 키 폐기 결재로 수행한다.

## 수용 기준

역할의 플랫폼 범위와 수신자를 모든 검토 화면에서 확인할 수 있다. 추가/해제가 다른 부여를 덮어쓰지 않는다. 조직/정책 편집 및 리소스 탐색의 미완료 부분은 기능 완료로 검수하지 않는다. 정책 만료와 조직 상속, 키 전용 역할은 서로 다른 관리 규칙으로 표시한다.
