# 공통 화면과 UI 규칙

## COM-01 로그인 — `/login` (M)

| 항목      | 화면 기획                                                                                                |
| --------- | -------------------------------------------------------------------------------------------------------- |
| 목적/진입 | Orion 및 백오피스 인증 시작. 비로그인 또는 세션 만료 시 진입                                             |
| 구성      | Orion 식별, 간결한 설명, Okta로 로그인 버튼, 한/영 선택, 설정 오류 안내. 뉴트럴 색상 사용                |
| 입력      | 비밀번호/토큰을 직접 받지 않는다                                                                         |
| 처리      | 버튼으로 배포 설정의 Orion 로그인 API에 GET 문서 이동. API가 Okta URL로 302/303 응답                     |
| 완료      | 서버의 OIDC 검증·세션 생성 후 허용된 화면으로 복귀. 플랫폼 활성 멤버십 확인은 서버 책임                  |
| 예외      | 로그인 URL 누락/잘못된 URL은 비활성 안내. 임의 URL 추측 또는 query로 전달된 외부 URL 이동 금지           |
| 검수      | 설정된 API만 호출하고 브라우저에 토큰을 보관하지 않는다. 실제 Okta 콜백/콘솔 가드는 미완료 사항으로 구분 |

## COM-02 홈과 내비게이션 — `/` (M)

- 홈은 메뉴 그룹별 진입 카드다. 통계 대시보드나 실제 감사 지표가 아니다.
- LSB: 사용자·조직 / 권한 관리 / 리소스 / API 접근 / 결재. 각 메뉴의 목록에서 상세로 이동한다.
- `/pages`는 워크스페이스, `/service-endpoints`는 서비스, `/actions`는 업무 도메인 메뉴를 활성 표시한다.
- 상단: 배포 정보, 언어 선택, 로그아웃. 배포 리전 선택을 사용자 입력으로 제공하지 않는다.
- 정책은 리소스 그룹에서 탐색하되 역할과 같은 종류의 객체로 취급하지 않는다.

## COM-03 접근 거부 — `/forbidden` (M)

조회 API 403 또는 열람 불가 문서 접근 시 공통 화면을 표시한다. 원래 문서의 제목·입력값·결재자·Secret 위치를 에러 화면에서 노출하지 않는다. 돌아가기/안전한 메뉴 이동을 제공한다. 메뉴가 숨겨졌는지와 무관하게 서버에서 직접 URL 접근을 검증해야 한다. 현재 경로는 오류 UI이며 HTTP 403 응답 엔드포인트 자체를 뜻하지 않는다.

## COM-04 로딩·빈 상태·오류·404 (M / 운영 적용 목표)

| 상태              | 표시/행동                                            | 금지                               |
| ----------------- | ---------------------------------------------------- | ---------------------------------- |
| 로딩              | 기존 문맥과 불러오는 중 표시, 중복 변경 실행 차단    | 빈 목록과 로딩 혼동                |
| 실제 0건          | 해당 유형의 빈 상태, 허용된 작업이 있을 때 진입 제공 | 권한 부족/조회 실패를 0건으로 표시 |
| 검색 0건          | 조건과 검색 결과 없음, 초기화                        | 원래 자료가 없다고 단정            |
| 조회 실패         | 일반 오류·재시도, 서버 진단 원문 숨김                | API 실패 시 데모 데이터 대체       |
| 존재하지 않는 ID  | 리소스별 not-found                                   | 이름으로 유사 객체 자동 선택       |
| 401               | 로그인 화면 또는 재로그인 안내                       | 세션 만료 상태로 변경 실행         |
| 403               | 공통 접근 거부 / 편집 폼 차단                        | 조회 권한을 변경 권한으로 간주     |
| 409/revision 충돌 | 새로고침 후 재선택·재검토 안내                       | 이전 검토 내용을 조용히 재적용     |
| timeout/처리 실패 | 현재 결과 확인 후 재시도                             | 결과 불명인 작업을 성공 표시       |

결재 문서는 존재 여부를 드러내지 않도록 열람 불가/찾을 수 없는 ID를 동일한 접근 거부로 처리할 수 있다(P18).

## COM-05 로그아웃과 언어 (M)

로그아웃은 Orion 세션 종료 API 성공 후 세션 및 데모 상태 쿠키를 정리하고 로그인으로 이동한다. 실패 시 성공 표시하지 않고 재시도한다. Okta 전체 SSO 로그아웃은 별도 계약이다. 한/영 전환은 현재 경로를 유지하고 UI·날짜 형식을 바꾼다. 사용자 입력, 카탈로그 이름, ID, YAML 키는 번역하지 않는다. 시간 표시와 입력은 배포 시간대를 기준으로 하고 서버 전송은 timezone을 포함한다.

## COM-06 목록 공통

- 화면 제목/설명 → 필요한 요약 → 검색·지원 필터 → 표 → 페이지 이동 순서.
- 행 이름은 상세 이동, 관계 개수는 관계 탭 이동. 단순 데이터 값을 버튼처럼 표시하지 않는다.
- 선택한 행 집합과 검색 결과 집합을 구분한다. 다른 페이지에 남은 선택이 있으면 개수와 해제 수단을 제공한다.
- 검색·필터·정렬·페이지 상태는 URL로 복원한다. 현재 BrowseTable은 표별 상태를 쓰며 5/10/20/50개 단위를 지원한다. 모든 표가 모든 필터/정렬을 구현한 것은 아니다.
- 기획된 열·필터와 실제 차이는 메뉴 문서에 기록한다. 현재 공통 목록은 클라이언트 처리 중심이므로 대용량 서버 검색/페이지 처리는 별도 계약이 필요하다.

## COM-07 상세 공통

상단 경로/객체명/설명/전체 작업 → 항상 보이는 기본 정보 → **하나의 탭 영역**으로 구성한다. 기본 정보는 별도 탭이 아니며 sticky 고정을 뜻하지 않는다. 관계 목록은 탭 안의 테이블로 통일한다. 탭 이름은 메뉴 이름을 사용하고 불필요한 ‘연결’ 접두사를 쓰지 않는다. 목록형 탭은 전체 개수 표시가 원칙이며 검색 건수와 구분한다. P18 일부 탭의 개수 미표시는 구현 차이로 남아 있다.

`?tab=<stable-id>`를 사용하고 새로고침·뒤로 가기를 지원한다. 잘못된 탭은 첫 관계 탭으로 대체한다. 관계의 0건 탭을 없애서 레이아웃이 변하지 않게 한다. 표 안 작업은 해당 탭에, Sync/영향도 같은 전체 작업은 상단에 둔다.

## COM-08 선택·검토 모달

1. **대상 선택/확인**: 이번에 바꿀 대상만 선택한다. 기존 항목, 추가/해제, 자동 포함된 항목을 구분한다.
2. **변경사항 및 영향도 검토**: 선택 대상과 결과, 권한 경로/리소스, 영향 대상, 차단 사유를 확인한 뒤 적용한다.

불필요한 단계 분할을 하지 않는다. 이전 단계로 돌아가도 선택을 보존한다. 검토는 권한 검증을 대신하지 않으며 서버가 적용 시 재검증한다. 실행 중 중복 제출·모달 닫기를 제한하고 실패 시 선택 문맥을 유지한다. 키 원문은 예외적으로 처리 직후 지우며 자동 복원하지 않는다.

동기화/롤백/영향도 모달 제목은 **영향도 검토**, 2단계는 **변경사항 및 영향도 검토**로 통일한다. 역할 부여·결재는 업무명을 제목으로 유지하되 선택→검토 구조를 따른다.

## COM-09 접근성과 개발용 화면

뉴트럴 배경과 명확한 구분선, 텍스트 상태 배지를 사용한다. 색만으로 상태를 구분하지 않는다. 입력은 접근 가능한 라벨, 에러는 알림 영역, 모달은 포커스 복귀, 탭은 키보드 조작을 제공한다. 좁은 화면은 문서 전체의 가로 넘침을 막고 긴 ID/hash는 줄바꿈 또는 표 내부 스크롤을 사용한다.

`/components`는 디자인 시스템 검토 화면이다. `/access-grants`, `/audit-logs`는 placeholder이며 신규 업무 완료 기준에 포함하지 않는다. 독립 동기화 이력 메뉴는 제공하지 않는다.

결재 작성의 공통 `RequestForm`은 페이지와 API 키 목록의 모달에서 재사용한다. `EndpointPicker`는 DataTable·Pagination·Field·Input·Button을 조합하며 선택 ID를 부모 폼에서 관리한다. 작성 중 검색·페이지 상태는 URL에 저장하지 않고 폼 세션 안에서 유지한다. `Dialog`의 `size="wide"`는 넓은 선택 폼에 사용하며 기존 모달의 기본 너비·포커스·닫기 규칙은 유지한다. 템플릿 생성/수정은 `TemplateEditorScreen`과 공통 Tabs를 공유한다.

### 통합 메뉴 및 데모 표시 규칙

결재와 결재 템플릿은 LSB의 결재 한 항목에 통합한다. `/approval-templates/*` 상세·편집 경로도 결재를 활성 표시한다. 제품 화면은 데이터 어댑터와 무관하게 동일하며 데모 사용자 선택·예제 배너·모의 실행 버튼을 표시하지 않는다. 내부 개발용 샘플 어댑터는 운영 API 연동과 분리하고 운영 환경에서는 기존 API 설정 검증을 유지한다. 통합 HTML도 동일한 컴포넌트를 사용하며 외부 연동 대신 브라우저 내 샘플 세션으로 동작한다.
