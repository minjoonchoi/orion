## 변경 동작

권한 신청을 별도 접수 배열에서 기존 approval-workflow 문서로 통합했다. 신청 내역에서 결재 문서 이동·미반영 신청 취소와 결재/권한 반영 상태를 제공한다. 기존 순차 결재·열람자·승인/반려 UI를 재사용하며, 신청 당시 역할·정책 ID·사용 기간을 문서에 저장한다. 최종 승인 후 담당 조직이 검토하여 반영한다. 완료된 기간부 부여는 내 접근 권한에 표시한다. API 키 전용 정보는 권한 문서에 표시하지 않는다.

MyAccess의 정책 기반 업무 목록은 보유 권한 탭 안으로 이동했다. 신청 내역에는 신청과 결재 상태만 표시한다. 새 템플릿은 읽기 전용이며 조회/작성 진입을 지원한다.

## 남은 운영 연동

실제 DB/Gateway 부여는 완료되지 않았다. API 모드에서는 기존 명령 API의 access-request/cancel/권한 execute 확장과 서버 제공 템플릿이 필요하다. 서버가 사용자·역할·결재선·담당 조직을 결정하고, 문서 완료와 기간부 역할 부여를 원자적으로 저장해야 한다. 역할의 정책 ID 집합은 재검증하지만 정책 본문 변경의 revision/hash 검증은 운영 서버 과제다.

현재 완료 문서의 권한 투영은 내 접근 권한/신청 화면 범위다. 다른 관리 화면의 개별 메모리 편집 상태와 영속 디렉터리 전체 통합을 의미하지 않는다. HTML의 전체 새로고침은 샘플 세션을 초기화한다.

기획서: prototype/overrides/docs/screens/13-approvals.md, 17-access-management.md. 실제 서버 연동·제품 적용 완료로 표시하지 않는다.
