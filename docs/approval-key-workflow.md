# 결재 템플릿과 API 키 후속 처리

## 경계

결재가 요청과 승인·합의를 소유하고 API 키는 완료된 결재의 후속 처리입니다. 요청하거나 최종 승인하는 순간에는 키·정책·역할을 생성하지 않습니다. 관리서비스 팀이 승인된 문서의 **후속 처리**에서 키 원문을 입력하고 명시적으로 실행합니다.

이 저장소는 Next.js UI와 Orion API 클라이언트입니다. 이번 변경에는 실행 가능한 데모 상태 모델, UI, 서버 액션/API 계약이 포함됩니다. AWS 자격 증명, 실제 Secrets Manager 쓰기, 영속 DB 및 API 키를 발급하는 관리서비스 서버는 포함하지 않습니다. 데모는 `demo-sha256:` hash만 만들어 흐름을 검증하며 원문은 보관하지 않습니다. API 모드에서 데모로 폴백하지 않습니다.

## 템플릿과 스냅샷

- 템플릿: ID, 버전, 이름, 처리 유형(issue/replace/revoke), 입력 필드, 순서가 있는 결재선.
- 기본 필드: 서비스 어카운트, 관리서비스, 해당 서비스의 엔드포인트 목록, Secret name, Secret value key, 요청 사유. 실행 계약에 필요한 여섯 필드는 필수이며 필드 라벨을 편집할 수 있습니다.
- 결재선 대상: 사용자, 조직, 요청자 팀장, 요청에서 선택한 관리서비스의 담당 조직. 카탈로그에서 선택하며 요청 시 동적 대상을 확정합니다.
- 조직 단계는 현재 멤버 중 한 명이 처리하면 완료됩니다. 조직 단계 완료 조건을 전원 승인으로 확장하는 기능은 이번 범위에 포함하지 않습니다.
- 발급 기본선: 요청자 팀장 승인 → 보안팀 합의 → 관리서비스 팀 합의.
- 교체/폐기 기본선: 요청자 팀장 승인 → 관리서비스 팀 합의.
- 실제 결재는 템플릿 전체, 입력값, 해석된 결재선, 담당 서비스 조직, 이전 엔드포인트 목록을 스냅샷으로 보관합니다. 템플릿 수정은 새 버전이 되며 기존 문서에 영향을 주지 않습니다.
- 템플릿 관리자만 템플릿 생성/수정을 수행합니다. 데모 관리자는 usr-001입니다. API의 actorId와 templateAdminIds는 인증된 서버가 결정해야 합니다.

## 조회와 업무 권한

- 문서 생성 시 요청자와 결재선 사용자·조직을 열람자에 자동 등록합니다. 조직 멤버를 개인별로 펼치지 않습니다.
- 목록, 검색, 건수, 상세 접근은 **동일한 열람자 목록**으로 제한합니다. 사용자 직접 등록 또는 등록 조직의 현재 멤버인 경우 허용합니다.
- 결재선 사용자와 결재선 조직의 현재 멤버는 사용자·조직 열람자를 수동 추가할 수 있습니다. 자동/수동 출처, 추가자, 시각을 기록합니다.
- 추가된 열람자는 자동으로 결재 처리나 열람자 추가 권한을 받지 않습니다.
- 현재 단계의 대상만 승인·합의를 처리하며 반려 시 후속 처리를 막습니다.
- 후속 처리는 최종 승인 완료 + 요청 시 확정된 관리서비스 조직의 현재 멤버 조건을 별도로 검증합니다.
- API 키/역할/정책을 볼 수 있더라도 해당 결재를 볼 권한이 생기지 않습니다. 키 상세의 결재 목록은 열람 가능한 문서만 표시합니다.

## 관리 ID, 키 버전, 권한

키 관리 ID는 발급 요청 시 예약하지만 실제 키 레코드는 성공적인 후속 처리 후 생성합니다. 동일한 서비스 어카운트·관리서비스 조합에 대해 병렬 요청을 금지합니다. 최초 발급은 전용 접근 정책과 Orion 역할을 만들고 역할을 서비스 어카운트에 부여합니다. 정책은 승인된 엔드포인트 목록만 허용합니다.

교체는 동일 관리 ID, 정책 ID, 역할 ID, Secret name, Secret value key를 재사용합니다. 변경할 엔드포인트와 사유만 새 결재에 담고 추가/삭제/유지를 검토합니다. 승인 후 담당 팀이 입력한 새 원문으로 기존 Secret 필드를 교체하고 정책 범위를 갱신합니다. 기존 키 버전의 hash와 처리 결재를 이력으로 보존합니다. 폐기도 같은 관리 ID의 이력입니다.

결재로 생성된 정책·역할은 역할/정책 목록과 상세, 서비스 어카운트의 역할/키 탭에서 조회할 수 있습니다. 이 권한은 YAML Sync나 직접 사용자 부여로 수정하지 않고 교체·폐기 결재를 통해 변경합니다.

기존 데모 키는 삭제하지 않고 **기존 API 키**에 읽기 전용으로 보존합니다. 기존 키에는 승인 스냅샷, Secret 저장 위치, hash가 없으므로 이를 추측해서 채우지 않습니다. 운영 데이터 이관 후 새 수명주기에 편입해야 합니다. 과거 데모 결재는 열람자 정보가 없어 새 목록에 자동 공개하지 않습니다.

## Orion API 계약

배포 설정의 환경/리전별 host, locale, 세션 쿠키 전달을 기존 `requestData`로 재사용합니다.

### GET /approval-workflow

`src/features/approval-workflow/model.ts`의 `stateSchema`를 만족하는 read model을 반환합니다. 사용자/조직/서비스/엔드포인트 카탈로그, 템플릿, 현재 사용자에게 공개 가능한 결재, 관리 가능한 키와 전용 정책·역할을 포함합니다. 서버가 인증된 사용자의 `actorId`, 템플릿 관리 권한 및 현재 조직 멤버십을 결정합니다. 브라우저 입력을 신뢰하지 않습니다. 보안상 금지된 문서는 응답에 포함하지 않습니다.

### POST /approval-workflow/commands

```json
{
  "expectedRevision": 17,
  "command": {
    "kind": "request",
    "templateId": "api-key-issue",
    "keyId": "",
    "requestId": "client-generated-uuid",
    "input": {
      "accountId": "sa-directory-sync",
      "serviceId": "svc-directory",
      "endpointIds": ["ep-users", "ep-orgs"],
      "secretName": "orion/directory/integration",
      "secretKey": "apiKey",
      "reason": "인사 디렉터리 연동"
    }
  }
}
```

- `request`: 템플릿 조회·검증 → 카탈로그 해석 → 스냅샷·열람자 작성. `requestId`로 중복 요청을 방지합니다.
- `template`: 관리자 검증 후 템플릿 새 버전 저장. 신규 버전 0을 제출하면 v1으로 생성합니다.
- `decide`: `id`, `decision: approved|rejected`. 순서, 현재 조직 멤버십과 문서 revision을 재검증합니다.
- `viewer`: `id`, `target:{kind:user|organization,id}`. 결재선 참가자만 추가합니다.
- `execute`: `id`, `secretText`. 키 원문 이외의 권한/저장 입력을 받지 않고 승인된 스냅샷에서 읽습니다. 폐기는 secretText가 빈 문자열입니다.
- 성공 응답: `{ "status": "ok" }`. 발급·교체 실행은 `{ "status": "ok", "hash": "server-generated-hash" }`를 반환하고 재조회 read model에도 같은 hash를 제공합니다. 원문을 응답하지 않습니다.
- 실패: 401/403/409 또는 검증 오류 HTTP 상태. 부분 성공을 200으로 반환하지 않습니다. timeout 후에는 같은 결재 ID로 실행 결과를 조회/재시도해 중복 생성하지 않아야 합니다.

### 실제 서버 실행의 필수 보장

1. 인증된 담당 팀과 승인 상태, 스냅샷 무결성, pair lock/revision을 검증합니다. 문서 ID를 실행 idempotency key로 사용합니다.
2. Secret JSON의 지정된 **최상위 필드**만 갱신하고 다른 필드를 보존합니다. 최초 발급은 이미 존재하는 필드를 덮어쓰지 않습니다. 교체는 동일 관리 ID가 소유한 필드만 갱신합니다. AWS 계정·리전·허용 Secret prefix는 서버 배포 설정에서 결정합니다.
3. 키 원문을 애플리케이션 로그/감사 이력/결재 스냅샷에 남기지 않습니다. 서버가 보안 정책에 맞는 hash를 생성합니다. 데모의 SHA-256 예시는 운영 hash 알고리즘 지침이 아닙니다.
4. Secret 저장과 권한 변경 및 DB 기록은 서로 다른 시스템입니다. 실행 작업을 영속적으로 기록하고 재시도·보상 처리를 구현해야 합니다. 새 키/Secret/권한 적용이 완료되기 전 기존 키를 폐기하지 않습니다. 실패하면 이전 Secret 버전 및 정책 범위를 복구하거나 복구 대기 상태로 기록합니다.
5. 성공 이후에만 키 hash/version, 역할 부여, 정책 범위, 실행자/시각, 결재 ID와 키 버전 이력을 확정합니다. 폐기는 키를 무효화하고 전용 역할 부여 및 소유 Secret 필드를 제거하되 다른 필드는 보존합니다.
6. 카탈로그의 동일한 엔드포인트 ID가 다른 서비스에 존재할 수 있으므로 endpointIds는 반드시 serviceId와 함께 검증/조회합니다.

## 검증

- `npm test`: 결재 생성/승인/실행 분리, 순서, ACL, 수동 열람자 제한, 스냅샷 불변성, 교체 및 폐기, revision 충돌과 원문 미보관을 포함합니다.

## 결재 목록 검색 회귀 검증

결재 목록과 템플릿 상세의 결재 탭은 공통 Documents/BrowseTable을 사용한다. 화면에 표시한 전체 제목(템플릿 이름 · 서비스 어카운트)을 그대로 검색해도 해당 문서가 남아야 한다. 표시·검색은 같은 제목 생성 함수를 재사용하며 ID와 요청 사유 검색도 유지한다. 관련 테스트와 CI 원인은 [회귀 검증 기록](ci-regression-2026-09-26.md)에 정리한다.
