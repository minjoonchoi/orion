# API 키 조회 화면

- `/api-keys`: 이름·ID·식별 표시·설명·소유자·조직 검색, 키 상태·조직 필터, 이름·발급일·만료일 정렬, 페이지 이동
- `/api-keys/[id]`: 기본 정보와 결재 이력 탭
- 기본 정보: ID, 이름, 설명, 마스킹된 식별 표시, 키 상태, 조직, 소유자, 발급·만료·최근 사용·폐기 시각
- 결재 이력: 요청 유형, 결재 상태, 요청자·결재자, 요청·처리 시각, 요청 사유, 결재 의견

결재 이력은 요청일 최신순으로 시작합니다. 검색, 결재 상태·요청 유형 필터, 요청·처리일 정렬과 페이지 이동을 제공합니다. `?tab=approvals`로 탭을 공유하며 새로 고침과 뒤로 가기를 지원합니다. 존재하지 않는 ID와 빈 이력은 별도 안내합니다. 소유자·요청자·결재자·조직 이름은 해당 상세 화면으로 연결합니다. 날짜와 시각은 한국 시간입니다.

## 예제 데이터와 연동 범위

`src/features/api-keys/fixtures.ts`와 `src/features/approvals/fixtures.ts`는 2026년 9월 23일 기준의 가상 메타데이터 스냅샷입니다. 키의 활성·만료·폐기 상태와 결재의 대기·승인·반려 상태는 서로 독립적으로 표시합니다. 만료일이 없는 경우와 사용·결재 기록이 없는 경우를 구분합니다. 상태는 조회 모델의 값을 사용하며 브라우저 시계로 추정하지 않습니다.

데이터 모델에는 실제 키 원문이나 복원 가능한 값이 없습니다. `displayHint`는 구분을 위한 가상 마스킹 표시입니다. 실제 연동 시에도 서버에서 가공한 메타데이터만 조회 어댑터로 전달해야 합니다.

서버 페이지는 `apiKeyRepository`를 호출합니다. 조직·소유자 관계, 발급·갱신·폐기 요청 유형은 조회 UI를 위한 예제 스키마이며 API 계약 확정 후 조정합니다. 발급·갱신·폐기 실행, 승인·반려 처리, API 연동과 실제 인증·인가 판정은 구현 범위에 포함하지 않습니다.

## 검증

`npm run check`, `npm run build`, `npm run test:e2e -- --workers=2`.
목록 탐색, 상세 관계 이동, 결재 이력 필터·페이지 이동, 탭 복원, 선택적 날짜·빈 이력·없는 ID, 접근성과 모바일 가로 넘침을 확인합니다.

결재 이력 ID를 선택하면 `/approvals/[id]` 상세 화면으로 이동합니다. 결재 예제 데이터는 결재 그룹과 공유합니다.
