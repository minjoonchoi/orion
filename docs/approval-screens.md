# 결재 그룹

LSB와 개요에 결재 그룹을 추가합니다.

| 메뉴        | 목록                  | 상세                       |
| ----------- | --------------------- | -------------------------- |
| 결재 템플릿 | `/approval-templates` | `/approval-templates/[id]` |
| 결재        | `/approvals`          | `/approvals/[id]`          |

템플릿 목록은 검색, 사용 상태·요청 유형 필터, 이름·수정일 정렬, 페이지 이동을 제공합니다. 상세에서는 ID, 이름, 설명, 요청 유형, 버전, 사용 상태, 작성 안내, 등록·수정 시각을 조회합니다.

결재 목록은 최신 요청순으로 표시하며 검색, 결재 상태·요청 유형·템플릿 필터, 요청명·요청일 정렬과 페이지 이동을 제공합니다. 상세에서는 요청 유형·상태, 적용 템플릿과 버전, 대상 API 키, 요청자·결재자, 요청·처리 시각, 요청 사유·결재 의견을 조회합니다. 미처리 요청과 미지정 결재자를 구분합니다.

API 키 결재 이력의 ID에서 결재 상세로 이동합니다. 결재 상세에서 적용 템플릿, 대상 API 키, 요청자·결재자의 상세로 이동합니다. 존재하지 않는 ID와 검색 결과 없음도 안내합니다.

## 데이터 범위

기존 API 키 결재 예제를 `src/features/approvals/fixtures.ts`로 옮겨 두 그룹에서 동일한 데이터를 사용합니다. 결재는 템플릿 ID를 명시적으로 참조하며 화면에서 현재 요청 유형으로 템플릿을 추측하지 않습니다. 예제 템플릿 ID는 해당 버전을 나타냅니다.

현재는 API 키 발급·갱신·폐기 유형의 가상 조회 데이터입니다. 템플릿 필드와 결재 관계는 예제 스키마이며 실제 API 계약 확정 후 조정합니다. 실서비스에서는 신청 당시 템플릿 버전/내용 보존 방식도 계약에 포함해야 합니다.

요청 생성, 템플릿 작성·수정, 결재선 편집, 승인·반려 실행, 알림 발송과 키 발급·폐기는 구현하지 않습니다. 데이터 원천만 옮겼으며 실제 계정 또는 키 원문은 포함하지 않습니다.

## 검증

`npm run check`, `npm run build`, `npm run test:e2e -- --workers=2`.
메뉴 활성화, 목록 탐색, API 키→결재→템플릿·키·사용자 탐색, 대기·반려 정보, 없는 ID, 접근성과 모바일 가로 넘침을 확인합니다.
