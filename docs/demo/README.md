# Orion 통합 UI 데모

[orion.html](orion.html)을 내려받아 브라우저에서 열면 됩니다. 서버 실행·설치·CDN 접속이 필요 없는 단일 파일입니다. 파일 미리보기에서 JavaScript를 실행하지 않는 환경은 브라우저로 열어주세요.

## 실제 코드와 일치시키는 방식

- `src/app`의 45개 page 경로를 자동 수집합니다. 목록·상세·탭·모달·검색·페이지 이동·언어·관계 이동은 실제 컴포넌트와 CSS를 그대로 사용합니다.
- 템플릿 생성/버전 수정, 결재 작성/검토/제출/열람자/승인, 승인 이후 키 처리, 역할 부여와 리소스 diff/영향도/동기화는 같은 업무 모델과 명령을 실행합니다. 화면만 흉내 낸 목업이 아닙니다.
- `tools/demo`는 Next 라우터/서버 쿠키/캐시/샘플 YAML 읽기를 브라우저 메모리로 대체합니다. 제품 화면에 사용자 전환이나 데모 전용 배너·버튼을 추가하지 않습니다.
- 로그인 사용자와 권한은 샘플 세션의 고정 사용자로 시작합니다. 승인 권한이 없는 문서를 HTML에서 임의로 승인할 수 없습니다. 현재 사용자에게 부여된 단계만 처리할 수 있습니다.

## 외부 연동 경계

Okta 로그인은 화면 이동만 시연합니다. 실제 Orion API·AWS Secrets Manager 호출, 실제 키 발급, 운영 인증/인가, 영속 저장은 수행하지 않습니다. CSP의 `connect-src 'none'`으로 외부 요청을 차단합니다. 저장소의 샘플 데이터만 포함하며 실제 키나 개인정보를 입력하지 마세요. 키 처리에서 사용하는 hash는 입력한 테스트 문자열로 계산하고 원문을 상태에 보관하지 않습니다.

변경 사항은 열린 문서의 메모리 안에 유지되며 새로고침/닫기 시 초기화됩니다. 브라우저의 뒤로/앞으로와 `#/경로` 링크를 사용할 수 있습니다. 접근 거부·미등록 템플릿·검증 실패도 같은 로직으로 표현합니다.

## 최신화 및 검증

```sh
npm ci
npm run demo:build
npm run demo:check
npm run check
npm run build
npm run test:e2e
npm run test:api
```

`demo:build`는 실제 코드·샘플 설정·모든 화면 기획서·AGENTS·빌드 도구·의존성 잠금 파일의 해시를 HTML에 포함합니다. CI의 `demo:check`는 재생성 결과와 커밋된 HTML이 정확히 일치하는지 검사합니다. 소스나 기획서만 변경하고 HTML을 갱신하지 않으면 실패합니다. 생성 파일은 수동 편집하지 않습니다.

화면 비교 테스트: `tests/e2e/standalone.spec.ts`. 변경된 기능은 실제 앱과 HTML 양쪽에서 검증합니다. 이 HTML은 서버 구현의 완료 증거가 아니라 실제 프런트엔드와 공유 로직의 통합 시연 결과입니다.
