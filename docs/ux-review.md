# Orion 전체 UI·UX 점검 및 개선

2026-09-25. 무채색 스타일을 기준으로 메뉴 전체, 목록·상세·관계 탭, 권한 부여, GitOps 변경 검토, 이력, 오류 화면을 점검했다. 실제 계정 대신 데모 데이터로 검증하며 운영 인증·인가 및 대규모 데이터 성능은 별도 범위다.

## 핵심 사용자 흐름

1. 사용자/조직을 검색 → 상세와 관계 조회 → 역할 선택 → 영향 검토 → 적용 완료.
2. 역할 조회 → 사용자·조직 부여 또는 정책·만료 설정 → 관계 변화 검토 → 적용.
3. 리소스 목록에서 유형·상태 필터 → 같은 화면에서 diff 대화상자 → 전체 Sync 영향 검토 → 적용 → 이력.
4. 정책 상세에서 Git 변경 검토로 이동 → 리소스·엔드포인트 처리 설정 비교 → 검토 → 적용.
5. 리소스 행 또는 상세에서 이력 열기 → revision의 변경 전후 확인 → 현재 상태와 복원할 정의·영향 검토 → 해당 리소스만 롤백.

## 남은 개선과 백엔드 의존성

- 리소스별 이력과 롤백의 필드별 diff·현재 관계 영향도·revision 충돌 검사를 구현했다. API는 리소스 필터 및 before/after 기록, 리소스 단위 복원 계약을 지원해야 한다. 정책 롤백은 기존 전체 정책 범위 확인을 유지한다. 서버의 영향도 preview token, 부여 보존·참조 검증·원자적 적용은 백엔드에서 보장해야 한다.
- 실제 접근 가능 여부는 관계만으로 단정하지 않는다. 정책 충돌·만료·조직 상속을 포함한 서버의 최종 권한 평가가 필요하다.
- 대규모 목록은 현재 수집 후 브라우저 검색 방식이다. 서버 페이지네이션·검색·정렬 API를 도입할 때 URL 상태를 그대로 전달하도록 확장한다.
- 정책 처리 handler별 사용자 친화적 변경 요약은 handler config 스키마 확정 후 추가한다. 현재 상세 설정은 펼쳐서 조회한다.
- 상태를 URL에 보존하므로 검색어도 주소에 남는다. 비밀값 검색은 제공하지 않으며 API 키 원문은 취급하지 않는다.

## 재현 가능한 검증

### 단일·선택 리소스 기준 영향도

리소스 목록의 행 및 상세에서 단일 리소스 영향도를 조회하고, 체크박스로 선택한 여러 리소스의 합산 영향도를 조회할 수 있다. 조회를 열 때 최신 환경·리전 snapshot을 요청하고 기준 revision을 명시한다. 상단에 조회 대상을 표시하며 선택 전체와 개별 리소스 사이에서 전환하면 집계와 부여 경로가 함께 좁혀진다. 정책·역할·조직·사용자는 조회 대상 리소스의 관계만 포함하고 중복 ID를 제외한다. 리소스는 kind+ID로 식별한다.

선택은 필터/페이지 이동과 새로고침에 걸쳐 URL에 유지된다. 현재 페이지 선택/해제, 개별 선택 해제, 전체 해제와 필터 밖 선택 수를 제공한다. 선택은 영향도 조회와 `선택 리소스 Sync`에 사용하며 `전체 변경 Sync`도 별도 제공한다. 선택 조회 모달에는 적용 액션이 없다.

단위 24개·관련 E2E 18개 통과. 공유 관계 중복 제거와 선택 밖 관계 제외, 종류가 다른 동일 ID, 만료 포함 여부, 다중/단일 범위 전환, 선택 유지, 상세 진입, 한국어·영어 및 모바일 접근성을 검증했다. lint·타입·포맷·production webpack build 통과. 실제 브라우저 캡처에서 선택 목록과 복수/단일 조회 화면을 확인했다.

### 영향도 관계 깊이 표현

영향도 검토의 평면 목록을 들여쓰기·관계선·유형 표시가 있는 접이식 목록으로 개선했다. 리소스 → 정책 → 역할 아래에 직접 부여 사용자를 표시하고, 조직 경유 사용자는 조직 아래 한 단계 더 깊게 표시한다. 기본은 주요 상위 관계까지 펼치며 필요한 하위 항목을 개별적으로 열 수 있다. 검색 시 일치하는 항목의 상위 경로도 보존한다. 숫자 요약은 검색과 무관한 전체 관계 기준이며 사용자는 중복을 제외한다.

리소스 Sync·롤백, 정책 Sync 및 역할 부여의 정책·리소스 탐색에 공통 목록 스타일을 적용했다. 목록 내부의 고정 높이 스크롤을 제거했고 모바일에서는 들여쓰기 폭을 줄인다. 실제 관계는 중첩 목록으로 전달하며 접기 버튼에 펼침 상태를 제공한다.

관련 E2E 15개 통과: 직접 부여/조직 경유 깊이, 검색 결과의 상위 경로 보존, 접기·펼치기, 빈 검색, 한국어·영어, 모바일 넘침 및 접근성 검사를 포함한다. lint·타입·포맷 및 production webpack build 통과. 실제 브라우저 캡처 `09-impact-depth.png`에서 5단계 관계을 확인했다.

### 리소스별 이력 후속 개선

별도 동기화 이력 메뉴와 목록 상단의 전체 이력 링크를 제거했다. 각 리소스 행/상세에서 해당 종류·ID의 변경 이력만 표시하며 삭제 완료 항목도 이력을 조회할 수 있다. revision별 before/after, 최초 동기화 직전 기준 버전, 현재와 동일한 버전의 롤백 비활성화를 제공한다. 롤백은 현재 정의와 선택한 정의의 diff·관계 영향도 검토 후 그 리소스만 복원하며 revision 충돌과 참조 무결성을 검사한다. API는 리소스별 롤백 전용 경로를 사용하며 기존 전체 롤백으로 대체하지 않는다.

후속 검증: 단위 테스트 23개 및 관련 E2E 8개 통과. 리소스별 이력 격리, 다른 정의/부여 보존, 삭제 이력, 목록/상세 진입, 새로고침 후 이력 유지, 한국어·영어와 모바일 접근성을 확인했다. lint·타입·포맷 검사 및 production webpack build 통과. 핵심 상호작용 7개를 재실행해 런타임 오류 없이 최신 화면 8장을 캡처했다.

### 기존 전체 점검 기록

최종 결과: 38개 경로·28개 상세 탭 순회, 핵심 상호작용 7개 통과. 자동 접근성 검사를 실행한 22개 목록/메뉴 경로의 WCAG A/AA 위반 0건, 23개 목록/메뉴 경로의 모바일 가로 넘침 0건. 상세 화면 접근성·404·언어·오류·키보드 흐름은 기존 E2E도 함께 사용했다. 단위 21개, E2E 52개(최초 49/50 통과 후 실패 1개 수정 재검증 및 신규 2개 포함), 모의 API 5개 통과. 프로덕션 webpack 빌드와 lint·타입·포맷 검사 통과.

단위 테스트는 롤백 시 현재 부여 보존 및 잘못된 참조 차단을 포함한다. API 모드의 운영 동작은 실제 서버 연동 전까지 완료로 판단하지 않는다.

### 상세·선택 목록·정책 Sync 흐름 통일

리소스 상세의 Sync와 목록의 선택 리소스 Sync가 같은 ‘대상 확인 → 변경·영향도 검토’ 대화상자를 사용한다. 정책 Sync는 리소스와 필수 상위를 포함하며 사유를 표시한다. 검토의 주 영향도는 선택 정책의 부여 역할·직접 사용자·조직·멤버를 기준으로 계산하며 연관 리소스의 추가 영향을 별도로 펼친다. 변경 전후는 항목별로 펼치고 최종 확인 후 단일 실행으로 적용한다. 선택하지 않은 변경은 Out of sync로 남는다.

정확한 API 계약과 원자 적용·부분 Sync 이력·scope별 롤백 의미는 `docs/resource-gitops.md`의 공통 Sync 계획 API를 따른다. 운영 API 구현이 없으면 이전 전체 Sync API로 대체 호출하지 않는다.

검증: 단위 29개·관련 E2E 21개, lint·타입·포맷·production webpack build 통과. 선택 범위 외 변경 보존, 의존성 생성, 결합 적용의 단일 revision, 인가 revision 충돌, 리소스별 이력 및 한·영 모바일 접근성을 확인했다. `scripts/sync-workflow-screens.mjs`로 상세·다중 선택·정책 대상과 영향도 화면 8장을 재현할 수 있다.

### 사용자·조직·서비스 어카운트 중심 영향도

대상 유형별 숫자와 목록을 우선 표시하고 대상마다 역할·정책 요약 및 펼칠 수 있는 전체 경로를 제공합니다. 직접 사용자와 조직 멤버 경로를 구분하고 서비스 어카운트는 기존 상세의 명시적 역할 관계로 계산합니다. 검색·대상 페이지 구분·경로 더 보기로 긴 목록을 제한합니다. 정책/역할 부여 변경 검토에서는 추가·해제 경로만 표시합니다. 영향도 데이터의 계정 정보가 누락되면 0으로 오인하지 않도록 미확인 상태를 표시합니다.

재현: `ORION_UX_PRODUCTION=1 node scripts/subject-impact-screens.mjs`. 사용자·조직·계정 영향도, 정책 Sync, 정책 부여 해제 및 영어 모바일 화면을 캡처합니다.

검증: 단위 33개, 관련 E2E 24개 통과(초기 23개 성공 후 다중 조직 fixture의 기대값 수정 및 해당 테스트 재검증). lint·타입·포맷·production webpack build 통과. 실제 브라우저 6장 캡처, 런타임 오류 및 영어 모바일 자동 접근성 위반 0건.

### 조직 경유 사용자 표시 간소화

영향도 사용자 목록과 숫자는 직접 역할이 부여된 사용자만 포함합니다. 조직은 독립 대상으로 유지하고 조직 멤버 펼치기와 조직 경유 사용자 경로를 제거했습니다. 리소스·정책 Sync, 롤백 및 부여 변경 검토의 공통 화면에 적용하며 실제 조직 멤버십·권한은 바꾸지 않습니다. 이전 확장형 사용자 집계를 보여주던 diff 요약 숫자도 제거했습니다.

## 영향 대상 통합 목록

사용자·조직·서비스 어카운트 탭을 제거하고 기본값이 전체인 통합 목록으로 변경했습니다. 상단은 클릭하지 않는 유형별 건수 요약이며 행에는 유형 배지와 역할·정책 요약을 표시합니다. 유형 선택은 검색 옆 필터로 제공하며 대상을 펼치면 기존 영향 경로를 확인할 수 있습니다. 조직 멤버 사용자는 계속 제외합니다.

리소스 단일·선택 영향도, Sync·롤백 및 역할·정책 부여 검토에 공통 적용했습니다. 서로 다른 유형에서 ID가 같아도 행을 구분합니다. 서비스 어카운트 정보가 누락된 경우 전체 집계를 ‘확인된 대상’으로 표현하고 미확인 안내를 유지합니다.

검증: lint·타입·포맷·단위 33개·production webpack build 통과. 관련 E2E 12개 통과(11개 최초 통과, 표시 순서를 가정한 테스트를 유형 포함 여부 검증으로 보완한 후 나머지 1개 재검증). 전체 유형 동시 표시, 검색·필터 복귀, 정책 Sync, 롤백, 영어 모바일 접근성 확인. 실제 화면 7장 캡처, 자동 접근성 검사 위반 0건.

## 검토·동기화 용어 통일

리소스 영향 조회, 리소스·정책 동기화, 리소스 롤백의 검토 모달 제목을 ‘영향도 검토’로 통일했습니다. 조회/동기화/복원 대상은 설명문과 대상 요약으로 구분합니다. 동기화 단계는 ‘대상 확인 → 변경사항 및 영향도 검토’, 최종 실행은 ‘동기화 적용’입니다. 역할·정책 부여 편집기도 검토 단계와 다음 단계 버튼에 같은 용어를 사용합니다. 한국어 화면의 동작명 Sync는 동기화로 통일하되 Synced / Out of sync 상태명은 유지합니다. 영어는 Review impact / Review changes & impact / Apply sync를 사용합니다.

검증: lint·타입·포맷·단위 33개·관련 E2E 24개·production webpack build 통과. 영향 조회·정책 동기화·상세/선택 동기화·권한 변경·롤백 및 한/영 모바일 흐름을 확인했습니다. 최신 실제 화면 15장 캡처, 캡처 중 자동 접근성 검사 위반 0건.

## 접근 대상 탐색과 정책을 포함한 변경 관리

리소스 그룹에 워크스페이스·페이지·서비스·엔드포인트·정책·변경 관리를 배치했습니다. 역할은 권한 관리 그룹으로 분리하며 접근 대상, 정책, 변경 관리 사이에 구분선을 사용합니다. 유형별 메뉴는 현재 적용된 데이터의 독립 목록을 표시합니다. 워크스페이스 → 페이지, 서비스 → 엔드포인트 및 상위 상세 탐색, 검색·정렬·필터·URL 상태 보존을 복원했습니다. 엔드포인트 메서드 필터는 API DTO의 7개 메서드를 모두 지원합니다.

변경 관리는 정책과 접근 대상 네 유형을 같은 목록에서 필터링·선택하며, 정책과 독립 리소스의 혼합 선택을 한 검토·적용으로 처리합니다. 정책 부여 대상과 필수 상위는 자동 포함하고 포함 사유와 중복을 정리합니다. 변경 전후 비교·영향도·선택 보존·해당 대상 이력을 유지합니다. 정책은 배포 관리 유형에만 추가하고 실제 접근 대상 ResourceKind 네 종류와 역할 → 정책 → 접근 대상 구조는 유지합니다.

정책 이력은 해당 ID가 포함된 실행으로 한정합니다. 기존 정책 rollback API의 실행 단위 복원 범위를 표시하여 함께 적용된 정책·리소스를 확인하고 복원하도록 합니다. 혼합 선택은 기존 selection 요청의 policies 모드에 resources를 허용하는 계약 확장입니다. 운영 API도 이 범위의 원자적 검증·적용을 지원해야 합니다.

검증: lint·타입·포맷·단위 34개·production webpack build 통과. 관련 E2E 32개 통과(기존 경로·집계 및 새 테스트 선택자를 보정하고 해당 실패 건만 재검증). 유형별 적용 상태 목록, 정책/리소스 혼합 선택의 부분 적용·1 revision·정책별 이력, 상세 관계, 한/영 모바일 접근성을 확인했습니다. 실제 화면 7장 및 캡처 중 자동 접근성 검사 위반 0건. 재현: scripts/resource-navigation-screens.mjs.

## 리소스·정책 단위 동기화

환경 전체를 단일 동기화 대상으로 보이게 하던 버전 카드와 전체 변경 동기화 버튼을 제거했습니다. 변경 관리 상단은 전체/Synced/Out of sync 항목 수를 표시하고 각 행에 단일 항목 동기화를 제공합니다. diff와 리소스 상세에서도 동일한 항목을 검토합니다. 변경 없는 행은 동기화 버튼을 비활성화합니다. 여러 항목은 체크박스의 명시적 선택을 통해 함께 검토하며 정책 부여 대상과 필수 상위 포함 사유를 유지합니다.

리소스 상세는 자체 Synced/Out of sync와 해당 항목의 실제 적용 이력을 표시합니다. 이력이 없으면 환경 revision을 대신 보여주지 않습니다. 공통 snapshot revision의 충돌 검사와 기존 정책 실행 단위 rollback API는 유지합니다.

검증: lint·타입·포맷·단위 34개·production webpack build 통과. 관련 E2E 23개 통과(19개 최초 통과, 명시적 선택으로 전환한 테스트의 이동·필터 조건 보정 후 4개 재검증). 단일 리소스만 적용, 다른 정책 변경 유지, 단일 정책의 관계 대상, 선택 적용·충돌 차단·이력·롤백·한/영 모바일 접근성을 확인했습니다. 실제 화면 8장 캡처 및 캡처 중 접근성 검사 위반 0건.

### YAML diff / 영향도 두 뷰

- 동기화 상태 셀은 중립색 점과 Synced / Out of sync만 표시합니다. 변경 검토는 행의 별도 동작으로 제공합니다.
- 리소스·정책 변경 검토와 공통 동기화 검토에 YAML diff / 영향도 탭을 적용합니다. 선택 항목과 preview는 뷰 전환 시 유지됩니다.
- 적용/예정 정의를 키 정규화한 YAML로 직렬화해 행 번호와 추가·삭제 행을 비교합니다. 원본 Git 파일 주석·서식 diff가 아니며, 삭제 정의는 state: absent를 표시합니다.
- 영향도는 기존 관계 기반 분석입니다. 최종 접근 허용 판정이 아니며 조직 경유 사용자는 포함하지 않습니다. 정책 동기화 시 리소스 및 필수 상위와 추가 영향 검토는 유지합니다.
- 재현: scripts/yaml-review-screens.mjs. YAML 알고리즘 단위 테스트와 리소스 단위 두 뷰 전환, 영어 모바일 접근성 E2E를 추가했습니다.

### 도메인 Action·복합 참조 기반 정의 관리

- workspace/pages, service/endpoints, domain/actions, policy의 간단한 YAML 문서와 scoped ref로 전환했습니다. 환경·리전과 revision은 배포/API 상태에서 관리합니다.
- 업무 도메인 메뉴, 부모 상세의 하위 항목 표, Action 상세, 엔드포인트별 Action 비교, 정책의 필드 선택·마스킹·unmask, 대상별 권한 평가를 추가했습니다. 하위 항목과 역참조가 같은 항목을 중복 표시하지 않도록 구분했습니다.
- 단일·선택 동기화는 같은 preview 토큰과 2단계 검토를 사용합니다. 의존성·참조 무결성·동시 변경·삭제 제한을 검증하고 개별 이력과 복원을 제공합니다.
