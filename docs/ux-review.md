# Orion 전체 UI·UX 점검 및 개선

2026-09-25. 무채색 스타일을 기준으로 메뉴 전체, 목록·상세·관계 탭, 권한 부여, GitOps 변경 검토, 이력, 오류 화면을 점검했다. 실제 계정 대신 데모 데이터로 검증하며 운영 인증·인가 및 대규모 데이터 성능은 별도 범위다.

## 핵심 사용자 흐름

1. 사용자/조직을 검색 → 상세와 연결 관계 조회 → 역할 선택 → 영향 검토 → 적용 완료.
2. 역할 조회 → 사용자·조직 부여 또는 정책·만료 설정 → 연결 변화 검토 → 적용.
3. 리소스 목록에서 유형·상태 필터 → 같은 화면에서 diff 대화상자 → 전체 Sync 영향 검토 → 적용 → 이력.
4. 정책 상세에서 Git 변경 검토로 이동 → 리소스·엔드포인트 처리 설정 비교 → 검토 → 적용.
5. 리소스 행 또는 상세에서 이력 열기 → revision의 변경 전후 확인 → 현재 상태와 복원할 정의·영향 검토 → 해당 리소스만 롤백.

## 남은 개선과 백엔드 의존성

- 리소스별 이력과 롤백의 필드별 diff·현재 관계 영향도·revision 충돌 검사를 구현했다. API는 리소스 필터 및 before/after 기록, 리소스 단위 복원 계약을 지원해야 한다. 정책 롤백은 기존 전체 정책 범위 확인을 유지한다. 서버의 영향도 preview token, 부여 보존·참조 검증·원자적 적용은 백엔드에서 보장해야 한다.
- 실제 접근 가능 여부는 연결 관계만으로 단정하지 않는다. 정책 충돌·만료·조직 상속을 포함한 서버의 최종 권한 평가가 필요하다.
- 대규모 목록은 현재 수집 후 브라우저 검색 방식이다. 서버 페이지네이션·검색·정렬 API를 도입할 때 URL 상태를 그대로 전달하도록 확장한다.
- 정책 처리 handler별 사용자 친화적 변경 요약은 handler config 스키마 확정 후 추가한다. 현재 상세 설정은 펼쳐서 조회한다.
- 상태를 URL에 보존하므로 검색어도 주소에 남는다. 비밀값 검색은 제공하지 않으며 API 키 원문은 취급하지 않는다.

## 재현 가능한 검증

### 단일·선택 리소스 기준 영향도

리소스 목록의 행 및 상세에서 단일 리소스 영향도를 조회하고, 체크박스로 선택한 여러 리소스의 합산 영향도를 조회할 수 있다. 조회를 열 때 최신 환경·리전 snapshot을 요청하고 기준 revision을 명시한다. 상단에 조회 대상을 표시하며 선택 전체와 개별 리소스 사이에서 전환하면 집계와 연결 경로가 함께 좁혀진다. 정책·역할·조직·사용자는 조회 대상 리소스의 연결만 포함하고 중복 ID를 제외한다. 리소스는 kind+ID로 식별한다.

선택은 필터/페이지 이동과 새로고침에 걸쳐 URL에 유지된다. 현재 페이지 선택/해제, 개별 선택 해제, 전체 해제와 필터 밖 선택 수를 제공한다. 선택은 영향도 조회와 `선택 리소스 Sync`에 사용하며 `전체 변경 Sync`도 별도 제공한다. 선택 조회 모달에는 적용 액션이 없다.

단위 24개·관련 E2E 18개 통과. 공유 연결 중복 제거와 선택 밖 연결 제외, 종류가 다른 동일 ID, 만료 포함 여부, 다중/단일 범위 전환, 선택 유지, 상세 진입, 한국어·영어 및 모바일 접근성을 검증했다. lint·타입·포맷·production webpack build 통과. 실제 브라우저 캡처에서 선택 목록과 복수/단일 조회 화면을 확인했다.

### 영향도 연결 깊이 표현

영향도 검토의 평면 목록을 들여쓰기·연결선·유형 표시가 있는 접이식 목록으로 개선했다. 리소스 → 정책 → 역할 아래에 직접 부여 사용자를 표시하고, 조직 경유 사용자는 조직 아래 한 단계 더 깊게 표시한다. 기본은 주요 상위 연결까지 펼치며 필요한 하위 항목을 개별적으로 열 수 있다. 검색 시 일치하는 항목의 상위 경로도 보존한다. 숫자 요약은 검색과 무관한 전체 연결 기준이며 사용자는 중복을 제외한다.

리소스 Sync·롤백, 정책 Sync 및 역할 부여의 정책·리소스 탐색에 공통 목록 스타일을 적용했다. 목록 내부의 고정 높이 스크롤을 제거했고 모바일에서는 들여쓰기 폭을 줄인다. 실제 관계는 중첩 목록으로 전달하며 접기 버튼에 펼침 상태를 제공한다.

관련 E2E 15개 통과: 직접 연결/조직 경유 깊이, 검색 결과의 상위 경로 보존, 접기·펼치기, 빈 검색, 한국어·영어, 모바일 넘침 및 접근성 검사를 포함한다. lint·타입·포맷 및 production webpack build 통과. 실제 브라우저 캡처 `09-impact-depth.png`에서 5단계 연결을 확인했다.

### 리소스별 이력 후속 개선

별도 동기화 이력 메뉴와 목록 상단의 전체 이력 링크를 제거했다. 각 리소스 행/상세에서 해당 종류·ID의 변경 이력만 표시하며 삭제 완료 항목도 이력을 조회할 수 있다. revision별 before/after, 최초 동기화 직전 기준 버전, 현재와 동일한 버전의 롤백 비활성화를 제공한다. 롤백은 현재 정의와 선택한 정의의 diff·연결 영향도 검토 후 그 리소스만 복원하며 revision 충돌과 참조 무결성을 검사한다. API는 리소스별 롤백 전용 경로를 사용하며 기존 전체 롤백으로 대체하지 않는다.

후속 검증: 단위 테스트 23개 및 관련 E2E 8개 통과. 리소스별 이력 격리, 다른 정의/부여 보존, 삭제 이력, 목록/상세 진입, 새로고침 후 이력 유지, 한국어·영어와 모바일 접근성을 확인했다. lint·타입·포맷 검사 및 production webpack build 통과. 핵심 상호작용 7개를 재실행해 런타임 오류 없이 최신 화면 8장을 캡처했다.

### 기존 전체 점검 기록

최종 결과: 38개 경로·28개 상세 탭 순회, 핵심 상호작용 7개 통과. 자동 접근성 검사를 실행한 22개 목록/메뉴 경로의 WCAG A/AA 위반 0건, 23개 목록/메뉴 경로의 모바일 가로 넘침 0건. 상세 화면 접근성·404·언어·오류·키보드 흐름은 기존 E2E도 함께 사용했다. 단위 21개, E2E 52개(최초 49/50 통과 후 실패 1개 수정 재검증 및 신규 2개 포함), 모의 API 5개 통과. 프로덕션 webpack 빌드와 lint·타입·포맷 검사 통과.

`docs/ux-review-results.json`에 화면 순회 기록을 남겼다. `ORION_UX_PRODUCTION=1`이면 빌드된 앱을 사용하며, `ORION_UX_INTERACTIONS_ONLY=1`은 기존 순회 결과를 유지하고 상호작용·스크린샷만 갱신한다.

`node scripts/ux-review.mjs`는 로컬 Next 서버와 Chromium을 실행하여 목록·상세·관계 탭·주요 사용자 흐름을 순회한다. 페이지별 접근성 결과, 모바일 넘침, 런타임 오류와 스크린샷은 `ORION_UX_OUTPUT` 경로에 저장한다. 선택적으로 `ORION_SCREENSHOT_FONT_DIR`에 로컬 Noto Sans KR fontsource 폴더를 지정해 캡처 글꼴을 보완할 수 있다. 자동 검사는 실제 사용자 테스트나 수동 스크린리더 검증을 대체하지 않는다.

단위 테스트는 롤백 시 현재 부여 보존 및 잘못된 참조 차단을 포함한다. API 모드의 운영 동작은 실제 서버 연동 전까지 완료로 판단하지 않는다.

### 상세·선택 목록·정책 Sync 흐름 통일

리소스 상세의 Sync와 목록의 선택 리소스 Sync가 같은 ‘대상 확인 → 변경·영향도 검토’ 대화상자를 사용한다. 정책 Sync는 연결 리소스와 필수 상위를 포함하며 사유를 표시한다. 검토의 주 영향도는 선택 정책의 부여 역할·직접 사용자·조직·멤버를 기준으로 계산하며 연관 리소스의 추가 영향을 별도로 펼친다. 변경 전후는 항목별로 펼치고 최종 확인 후 단일 실행으로 적용한다. 선택하지 않은 변경은 Out of sync로 남는다.

정확한 API 계약과 원자 적용·부분 Sync 이력·scope별 롤백 의미는 `docs/resource-gitops.md`의 공통 Sync 계획 API를 따른다. 운영 API 구현이 없으면 이전 전체 Sync API로 대체 호출하지 않는다.

검증: 단위 29개·관련 E2E 21개, lint·타입·포맷·production webpack build 통과. 선택 범위 외 변경 보존, 의존성 생성, 결합 적용의 단일 revision, 인가 revision 충돌, 리소스별 이력 및 한·영 모바일 접근성을 확인했다. `scripts/sync-workflow-screens.mjs`로 상세·다중 선택·정책 대상과 영향도 화면 8장을 재현할 수 있다.

### 사용자·조직·서비스 어카운트 중심 영향도

대상 유형별 숫자와 목록을 우선 표시하고 대상마다 역할·정책 요약 및 펼칠 수 있는 전체 경로를 제공합니다. 직접 사용자와 조직 멤버 경로를 구분하고 서비스 어카운트는 기존 상세의 명시적 역할 연결로 계산합니다. 검색·대상 페이지 구분·경로 더 보기로 긴 목록을 제한합니다. 정책/역할 연결 변경 검토에서는 추가·해제 경로만 표시합니다. 영향도 데이터의 계정 정보가 누락되면 0으로 오인하지 않도록 미확인 상태를 표시합니다.

재현: `ORION_UX_PRODUCTION=1 node scripts/subject-impact-screens.mjs`. 사용자·조직·계정 영향도, 정책 Sync, 정책 연결 해제 및 영어 모바일 화면을 캡처합니다.

검증: 단위 33개, 관련 E2E 24개 통과(초기 23개 성공 후 다중 조직 fixture의 기대값 수정 및 해당 테스트 재검증). lint·타입·포맷·production webpack build 통과. 실제 브라우저 6장 캡처, 런타임 오류 및 영어 모바일 자동 접근성 위반 0건.

### 조직 경유 사용자 표시 간소화

영향도 사용자 목록과 숫자는 직접 역할이 부여된 사용자만 포함합니다. 조직은 독립 대상으로 유지하고 조직 멤버 펼치기와 조직 경유 사용자 경로를 제거했습니다. 리소스·정책 Sync, 롤백 및 연결 변경 검토의 공통 화면에 적용하며 실제 조직 멤버십·권한은 바꾸지 않습니다. 이전 확장형 사용자 집계를 보여주던 diff 요약 숫자도 제거했습니다.
