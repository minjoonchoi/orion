# 역할·정책 조회 화면

- `/roles`: 이름·ID·설명 검색, 정책 부여 여부 필터, 이름·관계 수 정렬, 페이지 이동
- `/roles/[id]`: 기본 정보, 직접 부여 대상 사용자, 조직, 정책
- `/policies`: 이름·ID·설명 검색, 리소스 지정 여부 필터, 이름·관계 수 정렬, 페이지 이동
- `/policies/[id]`: 기본 정보, 서비스, 서비스 엔드포인트, 워크스페이스

상세 탭은 `?tab=users`, `organizations`, `policies` (역할), `services`, `endpoints`, `workspaces` (정책)로 공유합니다. 잘못된 탭은 기본 정보로 표시하고, 없는 ID는 찾을 수 없음 화면으로 안내합니다.

사용자·조직 상세의 역할 링크와 역할 상세의 사용자·조직 링크를 양방향 관계했습니다. 정책 목록에서 정책 상세로 이동할 수 있습니다. 서비스·엔드포인트·워크스페이스의 이름을 선택하면 각 리소스 상세 화면으로 이동합니다.

## 데이터 범위

`src/features/access/repository.ts`는 가상 데이터 조회 어댑터입니다. 기존 사용자·조직의 역할 관계를 재사용하며, 정책과 리소스 관계는 예제 데이터입니다. API 계약 확정 후 서버 페이지가 사용하는 이 어댑터를 교체합니다.

직접 관련된 관계만 조회합니다. 조직 역할 상속, 서비스의 모든 엔드포인트에 대한 권한 부여, Allow/Deny 우선순위나 유효 권한 판정은 가정하지 않습니다. 정책 생성·수정·삭제와 실제 인증·인가 연동은 포함하지 않습니다.

## 검증

`npm run check`, `npm run build`, `npm run test:e2e -- --workers=2`.

목록 검색·필터·정렬·페이지 이동, 사용자↔역할↔조직과 역할→정책 탐색, 상세 탭 URL과 뒤로 가기, 빈 관계, 없는 ID, 접근성 및 모바일 가로 넘침을 검증합니다.
