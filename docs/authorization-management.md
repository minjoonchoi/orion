# 권한 편집과 영향 범위

## 화면

| 진입 화면                                 | 작업                                                                                                   |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 사용자·조직 상세 → 역할 부여              | 직접 부여 역할 선택/해제. 역할별 정책, 허용/거부, 만료, 4종 리소스 미리보기                            |
| 역할 상세 → 역할 부여 관리                | 사용자·조직에 역할 부여/해제. 정책별 연결 및 만료 시점 설정                                            |
| 정책 상세 → 리소스 연결과 정책 효과       | 워크스페이스·페이지·서비스·엔드포인트 각각 복수 선택. 모든 연결 리소스에 하나의 allow/deny 효과 적용   |
| 4종 리소스 상세 → 리소스 수정과 영향 범위 | 이름·설명 및 페이지/엔드포인트 경로, 엔드포인트 메서드 수정. 정책→역할→직접 사용자/조직 멤버 연결 탐색 |

변경은 편집 → 검토 → 적용 순서입니다. 검토 전에는 서버에 저장하지 않습니다. 만료 입력은 브라우저 시간대로 받으며 ISO UTC로 전송합니다. 표시 날짜는 기존 배포 시간대 설정을 사용합니다. 만료는 정책 자체가 아닌 **역할과 정책 사이의 연결**에 속합니다. `null`은 무기한입니다.

영향 탐색은 직접 연결을 기준으로 합니다. 사용자 수는 여러 경로의 중복을 제거합니다. 조직 멤버를 통한 간접 경로와 직접 부여 경로를 구분합니다. 만료된 연결은 기본적으로 제외하고 별도 체크박스로 조회합니다. 검색은 정책·역할·조직·사용자 이름으로 해당 전체 경로를 찾습니다. 각 항목은 기존 상세 화면으로 이동할 수 있습니다. 서비스나 워크스페이스 선택이 하위 엔드포인트·페이지를 자동 포함하지 않습니다. 충돌 정책의 최종 허용/거부 판정과 만료 적용은 서버 책임입니다.

## 권한 오류와 로그아웃

일반 조회의 API 403은 공통 `/forbidden` 화면으로 이동하고, 401은 `/login`으로 이동합니다. `/forbidden`은 리다이렉트된 UI 경로이며 HTTP 상태 403 자체를 반환하는 엔드포인트는 아닙니다. 실험적 Next authInterrupts는 사용하지 않습니다. 편집 데이터 조회·저장 중 403은 동일한 AccessDenied 컴포넌트를 표시하고 편집 폼을 숨깁니다. 오류 본문/민감한 진단 정보는 브라우저에 노출하지 않습니다.

상단 로그아웃은 서버 액션에서 `POST {baseUrl}/auth/logout`을 호출합니다. 백엔드는 Orion 세션을 무효화하고 204 또는 `{"status":"signed_out"}`을 반환해야 합니다. 401은 이미 종료된 세션으로 처리합니다. 성공 후 UI 호스트의 지정된 세션 쿠키와 예제 세션을 지우고 `/login`으로 문서 이동합니다. 실패 시 로그아웃 완료로 표시하지 않고 세션을 유지하며 재시도를 제공합니다. 언어 선택은 유지됩니다.

Okta 전역 SSO 세션 종료가 필요하면 백엔드에 별도 RP-initiated logout 계약을 추가해야 합니다. 현재 기능은 Orion 세션 종료입니다. Domain 쿠키를 발급하는 배포에서는 백엔드 세션 무효화가 필수이며, 쿠키 Domain/Path 정리도 배포의 인증 프록시와 일치시켜야 합니다.

## API 계약 (백엔드 구현·합의 필요)

기존 런타임 API base URL, locale, region, allowlist 세션 쿠키 전달 설정을 재사용합니다. Next Server Actions의 동일 출처 검증을 사용하며 별도의 브라우저 직접 API 호스트는 없습니다.

### GET `authorization/graph`

`{ "data": Graph }`를 반환합니다. 정규화된 Graph 필드는 `src/features/authorization/model.ts`의 `graphSchema`에 정의되어 있습니다.

- `revision`: 현재 그래프의 정수 버전
- `users`: `{id,name}[]`
- `organizations`: `{id,name,memberIds[]}[]`
- `roles`: `{id,name,description,userIds[],organizationIds[],bindings:[{policyId,expiresAt}]}[]`
- `policies`: `{id,name,description,effect:"allow"|"deny",resources:[{kind,id}]}[]`
- `resources`: `{id,kind,name,description,path,method}[]`; 경로나 메서드가 없는 유형은 빈 문자열
- `kind`: `workspaces`, `pages`, `services`, `service-endpoints`

서버는 인증된 관리자가 조회·편집할 수 있는 범위만 반환해야 합니다. 모든 참조는 그래프 내 엔티티로 해석되어야 합니다. 목록을 임의로 잘라 반환하면 영향 범위가 불완전해지므로, 대규모 환경에서는 검색/분할 로딩 계약을 추가해야 합니다. 현재 편집기는 한 번에 완전한 관리 범위 그래프를 받습니다.

### POST `authorization/changes`

요청은 `{revision, change}`이고 응답은 저장 후 **전체 Graph**를 담은 `{data: Graph}`입니다. 서버에서 revision 확인과 변경 적용을 하나의 트랜잭션으로 수행해야 합니다. 각 변경은 아래 필드 집합 전체를 교체합니다.

| change.type    | 필드                                                  |
| -------------- | ----------------------------------------------------- |
| `subjectRoles` | `subjectKind: users                                   | organizations`, `id`, `roleIds[]` |
| `grants`       | `roleId`, `userIds[]`, `organizationIds[]`            |
| `bindings`     | `roleId`, `bindings:[{policyId,expiresAt:string       | null}]`                           |
| `policy`       | `policyId`, `effect:allow                             | deny`, `resources:[{kind,id}]`    |
| `resource`     | `kind`, `id`, `name`, `description`, `path`, `method` |

서버는 모든 요청마다 권한, 대상 존재 여부, 리소스 유형, 중복, 만료 시점, 정책 연결의 최소 1개 리소스, 리소스 필드 제약을 검증해야 합니다. UI의 검토 단계는 인가 검증을 대체하지 않습니다. 읽기 전용 API DTO에도 저장 결과를 반영해야 기존 목록·상세가 일치합니다. 정책 read DTO에 `effect`, `pageIds`, 정책 상세에 `pages` 필드를 추가했습니다(이전 응답과 호환되는 선택 필드).

- 401: 재로그인 안내
- 403: 공통 권한 오류 UI
- 409: 동시 변경 충돌 안내; 다시 불러와 재편집
- 기타 오류: 성공으로 처리하지 않고 재시도 안내

## 예제 모드

실제 저장 API가 없는 환경에서도 전체 UX를 확인할 수 있습니다. 예제 그래프는 HttpOnly 세션 식별자로 브라우저별 분리된 서버 메모리에 보관하며, 기존 목록·상세 어댑터에도 변경 결과를 투영합니다. 서버 재시작 또는 마지막 저장에서 1시간이 지나면 초기화됩니다. 동시 변경은 revision으로 방지합니다. 예제 모드는 영구 저장소나 실제 권한 판정기가 아닙니다. API 모드에서는 이 예제 저장소를 사용하지 않습니다.

## 검증

`npm run check`, `npm run build`, `npm run test:e2e -- --workers=2`, `npm run test:api`.

단위 테스트는 참조 검증, 중복, 만료 범위, 직접/간접 영향 경로를 확인합니다. 브라우저 테스트는 부여·만료·deny 정책·페이지 연결·편집 결과 반영·접근성·영문·모바일·로그아웃을 확인합니다. 모의 HTTP API 테스트는 실제 POST 요청·revision 충돌·403·로그아웃 실패 및 성공을 검증합니다. 실제 Orion/Okta 서비스와의 통합은 별도 백엔드 환경에서 검증해야 합니다.
