# 현재 정책 계약

독립 정책·직접 부여의 현행 계약은 [독립 정책과 부여](19-independent-policies.md)를 따른다. 기존 ID/API의 호환 동작과 운영 미완료 범위를 함께 구분한다.

# 도메인 정책

정책은 도메인 Action의 허용/거부 그룹이다. name/effect/actions를 가지며 요청/응답 규칙은 소유하지 않는다. 정책을 역할에 부여하는 작업은 역할 상세의 책임이다.

## 탐색과 상세

독립 LSB 메뉴 대신 도메인 상세 정책 탭에서 탐색한다. 신규 상세 /policies/{domain}~{policy}는 allow/deny, 포함 Action, 관계, 동기화 이력, YAML을 보여준다. Action을 클릭하면 같은 Action 상세로 이동한다. 미부여 Action은 도메인 Action 탭에 계속 나타난다.

실행 정책 합성은 동일 Action에 대해 deny 우선, allow 없음은 거부다. 서로 다른 Action의 req/res 규칙을 합치지 않는다. 실제 서버 인가 및 신규 정책의 기존 플랫폼 역할 부여 통합은 후속 범위다.

## 기존 계약 호환

기존 /policies/{legacyId} 정의/API 화면 및 결재 관리 정책은 기존 계약으로 유지한다. API 키 발급/교체/폐기와 열람 동작을 보존한다. 구형 정책 응답 설정을 새 Action으로 조용히 변환하거나 기존 부여를 삭제하지 않는다. 이관 시 안정적인 복합 식별자 매핑과 역할 부여 검토가 필요하다.

## 정책·신청·운영 탐색 검토 보완

정책 목록의 API 키 결재 관리 정책 전용 영역은 제거한다. 이는 기존 키 결재의 자동 생성 정책이며 API 키 상세/서비스 어카운트/관련 결재에서 추적한다. 독립 YAML 정책 목록과 혼합 집계하지 않는다.

접근 확인은 설정·운영 그룹의 운영 진단 기능이다. 일반 사용자의 내 접근 권한과 구분한다. 실제 메뉴/경로의 운영 접근 제어는 서버 권한 연동이 필요하다.

권한 신청 승인은 기존 결재 시스템으로 일원화한다. 요청 제출 → 권한 신청 결재 문서 → 승인/반려 → 승인 후 권한 부여 처리 순서다. 결재 상태와 권한 반영 상태를 구분하고 승인만으로 부여 완료로 표시하지 않는다. 신청자·플랫폼·역할·사용기한·사유와 검토 시점 권한을 결재 문서에 보관한다. 신청 내역에서 같은 결재를 추적하며 별도 승인 엔진을 만들지 않는다. 현재 access-ui requests는 별도 메모리 접수 어댑터이므로 결재 문서 생성/권한 반영 연결은 미완료다. 새 시안은 이 제한을 신청 화면에서 명시한다.

펼침 영역은 summary 뒤에 공통 ui-disclosure-body/ui-layout-stack을 배치한다. details 자체에 grid gap을 적용하지 않는다. summary-본문 및 카드 사이 간격은 section-gap, 카드 내부는 field-gap, 버튼 사이는 action-gap을 사용한다. 상세 근거/데이터 범위·권한 변경 검토·YAML 비교·이력 펼침을 같은 규칙으로 확인한다.
