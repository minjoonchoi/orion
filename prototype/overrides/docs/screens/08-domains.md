# 현재 정책 계약

독립 정책·직접 부여의 현행 계약은 [독립 정책과 부여](19-independent-policies.md)를 따른다. 기존 ID/API의 호환 동작과 운영 미완료 범위를 함께 구분한다.

# 업무 도메인과 Action

도메인은 플랫폼·workspace와 독립된 제품 요건이다. domain.scopes/actions/policies를 함께 정의한다. Action은 도메인에 종속되며 domain/id로 식별한다. 신규 YAML 화면은 구현됨(메모리 어댑터), 운영 API 연동은 미완료.

## DOM-01 목록 /domains

기존 정의 목록과 신규 YAML 정의 목록에서 이름/식별자 검색·정렬·페이지 이동을 제공한다. 호환 기간의 구형 정의는 기존 상세를 유지한다. 파일명은 식별자가 아니다.

## DOM-02 상세 /domains/{id}

상단 이름·ID·상태·DB revision·원본 파일과 Sync 진입. 탭은 Action → 정책 → 조회 범위 → 사용 페이지 → 관계 → 동기화 이력 → YAML. Action은 정책에 연결되지 않아도 목록에 표시한다.

## ACT-02 상세 /actions/{domain}~{action}

엔드포인트의 서비스·method·path를 표시한다. request/response는 Action.endpoint 하위 규칙이다. 요청 표는 입력 전달/source 주입/scope 주입, 응답 표는 필드 선택·민감정보 마스킹·원문 반환을 보여준다. 로그 마스킹은 원문 반환과 별도다. 원본 엔드포인트 명세를 확인할 수 있고 제외 필드는 펼쳐 확인한다. 연결 정책·페이지에서 동일 Action 상세로 이동한다.

엔드포인트 원본 필드에 존재해도 Action에 없으면 요청 전달/응답 반환에서 제외한다. 필요한 요청은 문자열 항목으로 명시한다. 필수 요청 누락, 타입/참조 오류는 검증 대상이다. 다른 Action의 권한을 합쳐 원문 반환하지 않는다.

## Scope 상세 /scopes/{domain}~{scope}

전사 조직 코드 매핑과 참조 Action을 제공한다. 적용된 범위와 Git 변경 범위를 비교한다. 빈 매핑은 무제한 조회가 아니다. 상위 조직 자동 상속 없음.

기존 /domains/identity 등 이전 규격 URL과 기존 권한 평가 API는 호환 기간 동안 유지한다. 신규 정의의 운영 인가 평가와 동일하다고 표시하지 않는다. 신규 역할 부여 연결/서버 평가/전체 마이그레이션은 후속 통합 과제다.
